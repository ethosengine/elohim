# Horizon scan — 2026-08-13 (topic-scoped: context engineering / agent harnesses)

## Summary (≤4 sentences — chronicle pointer)

Operator-invoked scan of the context-engineering literature rather than the quarterly memory-substrate sweep: the field has converged, across OpenAI, Anthropic (three separate posts), and Arize, on treating the context window as a **projection of durable state** rather than an accumulating transcript, with the highest-signal artifact being Anthropic's managed-agents **session log that lives outside the harness** — making compaction and handoff the same operation over one append-only log. Our `plant-eprfs-*` family already implements exactly this inversion for *tooling artifacts* while the field implements it for *run state*, and our REA-valueflows-over-EPRs layer (556 active commitments, `commitment:claim:` state machine) is a richer, peer-native version of the ticket boards every team improvised — but nothing re-projects any of it into the window mid-run, which is the one real gap. `.epr-meta` should be renamed in our own thinking as **stigmergic System 2**, which partly supersedes the 2026-06-04 Beer reading's "System 2 is underbuilt" finding. Full trace, repo catalogue, and verdicts: `genesis/research/context-engineering-primary-sources-cross-pollination-2026-08-13.md`.

## Horizon delta since 2026-05-14

- **Source**: [Scaling managed agents](https://www.anthropic.com/engineering/managed-agents) (2026-04-08).
  **Finding**: Durable session log outside the harness (`getSession`/`emitEvent`/`wake`/`getEvents`); the window is a transform over it; original events survive compaction.
  **Implication**: The clean primitive for "handoff and compaction, consistently." Our durable layer is stronger on identity/provenance but does not capture the run and does not re-project.
  **Disposition**: **ELEVATE**.

- **Source**: [How to build planning into your agent](https://arize.com/blog/how-to-build-planning-into-your-agent/).
  **Finding**: The plan is rebuilt from state on every loop iteration and pinned immediately after the system prompt, ahead of history; `finish` refuses while tasks are pending.
  **Implication**: The mechanism behind the whole "progressive context shaping" idea, and the spec for a per-turn habits/commitment projection.
  **Disposition**: **ELEVATE**.

- **Source**: [Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps) (2026-03-24) vs [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (2025-11-26).
  **Finding**: Four months apart, the sprint construct *and* context resets were removed on a model-tier upgrade; planner and evaluator kept as load-bearing.
  **Implication**: Direct external statement of our "instrument with no reader" failure mode. Every scaffold needs a stress test — we have the mechanism (`retire-when:`), the field has only the lesson.
  **Disposition**: **WATCH** (re-read at each model-tier landing).

- **Source**: [When to use multi-agent systems](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them) + [multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system).
  **Finding**: Multi-agent is a read-heavy technique; splitting write work by role on a shared surface is an anti-pattern ("each handoff loses context"; agents spent more tokens coordinating than working).
  **Implication**: External corroboration of `[[feedback_subagent_disjointness_read_write]]`. We fan out onto one worktree routinely.
  **Disposition**: **WATCH**.

- **Source**: [How Claude Code is used in practice](https://www.anthropic.com/research/claude-code-expertise) (~400k sessions).
  **Finding**: Humans make ~70% of planning decisions, Claude ~80% of execution decisions; domain expertise (not coding background) drives yield (28-33% vs 15% verified success).
  **Implication**: A gate-placement rule. `/memory-ceremony` Phase 1 escalates an *execution* decision (which top-ranked surface to rewrite) that the ceremony's own measure already answers.
  **Disposition**: **ELEVATE** (operator-observed the same anti-pattern independently, 2026-08-13).
