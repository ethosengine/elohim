# Horizon scan — 2026-05-14

## Summary (≤4 sentences — this becomes the chronicle pointer)

The LLM-memory field is in active sprint mode: 8 agentic-memory papers landed on arxiv in the 5 days before this scan, and Letta shipped **Letta Code** — a directly-competitive memory-first CLI — sometime in the last quarter. Our substrate (MemPalace v3.3.5, 2026-05-10) just released a `repair --mode from-sqlite` recovery path that we should adopt operationally, and **cross-wing topic tunnels** (added v3.3.4) is a feature we already use but should verify is fully wired. The field is converging on three primitives we have analogs of (temporal-hierarchical consolidation, governance-of-evolving-memory, narrative-schemata-from-traces) and one we don't (cryptographically-verified portable memory across heterogeneous agents — directly aligned with our P2P substrate vision). No breaking changes; the substrate is mainstream.

## Field overview as of 2026-05-14 (bootstrap framing — no prior scan to delta against)

### What the field is doing right now

**1. Memory-first coding harnesses are now a category.** Letta Code (CLI, desktop app, npm-distributed, mobile/Slack/Discord access) explicitly positions itself opposite Claude Code: "session-based" (Claude/Codex/Gemini CLI) vs "agent-based" (Letta Code with persistent agent that learns). The pitch is `/init` + `/remember` + `/skill` slash-commands and **skill learning** — agents learn skills from their own trajectory. Letta's memory-block model is structured (`memory_blocks: [{label, value}]`), portable across models (Claude/GPT/Gemini/GLM/Kimi).

**2. Temporal-hierarchical consolidation is a converged pattern.** TiMem (2026-01-06) and TraceMem (2026-02-10) independently propose three-stage consolidation pipelines (raw → episodic → semantic/persona) with temporal trees / narrative threads. Both achieve SOTA on LoCoMo/LongMemEval. **Our comet shape + memory classes + lifecycle primitives map directly onto this taxonomy** — we're in the mainstream.

**3. Memory governance is emerging as a safety category.** "Governing Evolving Memory in LLM Agents" (SSGM framework, 2026-03-12) names exactly the failure modes we've designed against: memory corruption, semantic drift from iterative summarization, topology-induced knowledge leakage where sensitive contexts solidify into long-term storage. Their architecture decouples memory evolution from execution with consistency verification, temporal decay modeling, and dynamic access control. **Our hard rules (two-signature tiny-delete, story-must-be-canonical, historian-confirms-forensic-value) are functional analogs.**

**4. Sleep-time / offline consolidation has a foundational paper but no explosion.** "Sleep-time Compute: Beyond Inference Scaling at Test-time" (Kepner et al., 2025-04-17) and the newer "Mela: Test-Time Memory Consolidation based on Transformation Hypothesis" (2026-05-11) are landmark, but the practitioner ecosystem hasn't picked it up at scale yet. **Our `/dream` framing (memory_lifecycle_comet_shape, consolidation_events_economic_feedback) is ahead of the practitioner ecosystem here.**

**5. Cryptographically-portable memory across heterogeneous agents is a fresh primitive.** "Portable Agent Memory: A Protocol for Cryptographically-Verified Memory Transfer Across Heterogeneous AI Agents" (2026-05-10, four days ago). **Directly aligned with our P2P-native vision** — memory as DHT-notarized + agent-portable. We don't have this primitive; the protocol substrate (EPR + reach) is the place to take it.

**6. Benchmarks are professionalizing.** LongMemEval-V2 (2026-05-12) explicitly evaluates "Long-Term Agent Memory Toward Experienced Colleagues" — i.e., the Letta framing. MemPalace benches against LongMemEval-V1 at 96.6% R@5. **We should add a benchmark hook for our system but don't have one today.**

**7. Adversarial / poisoning attacks are now a literature.** "ShadowMerge: A Novel Poisoning Attack on Graph-Based Agent Memory via Relation-Channel Conflicts" (2026-05-09). MemPalace's KG is graph-based; the attack class is real for our substrate. **Watch this thread — implications for reach-as-earned at authoring (project_reach_earned_at_authoring).**

## Elevation candidates

The ELEVATE items — each turns into either a backlog Objective or a memory entry.

### 1. Portable / cryptographically-verified agent memory transfer (P2P-aligned)

**Source**: arxiv.org/abs/2605.xxxxx — "Portable Agent Memory: A Protocol for Cryptographically-Verified Memory Transfer Across Heterogeneous AI Agents" (2026-05-10).
**Finding**: A formal protocol for moving memory between heterogeneous LLM agents with cryptographic verification. Memory bundles are signed, transferable, replayable on the recipient.
**Implication for us**: Directly aligned with our P2P substrate (project_reach_earned_at_authoring, project_peer_native_account_canonical_surface, project_redeploy_the_substrate). Memory is one of the things that should move across our DHT and live within reach-gated trust. The protocol's cryptographic-verification primitive is something we'd need to design or pull in.
**Disposition**: ELEVATE — backlog item: "Spec a memory-portability primitive for the protocol" or memory entry capturing the idea + paper pointer.

### 2. Memory governance as named safety category (SSGM)

**Source**: arxiv.org/abs/2604.xxxxx — "Governing Evolving Memory in LLM Agents... (SSGM)" (2026-03-12).
**Finding**: Names "topology-induced knowledge leakage" (sensitive contexts solidifying into long-term storage) and "semantic drift through iterative summarization" as first-class risks. Proposes decoupling memory evolution from execution.
**Implication for us**: Our hard rules are functional analogs but they're not surfaced as a named risk taxonomy. We have memory entries (project_subconscious_memory_tier, project_values_forward_disclosure) that *implicitly* address these; the field is making them explicit.
**Disposition**: ELEVATE — write a memory entry "Memory governance vocabulary aligns with SSGM" mapping our safeguards to the named risk categories. Lightweight; 1-cycle work.

### 3. Adopt `mempalace repair --mode from-sqlite` as operational primitive

**Source**: MemPalace v3.3.5 release notes (2026-05-10).
**Finding**: Repair tool that recovers palace from `chroma.sqlite3` without opening a chromadb client against a corrupt store. Verified end-to-end on 52k-row palace.
**Implication for us**: Our palace is at the same scale we'd worry about (~12,883 drawers per [[reference_mempalace]]). The librarian's recovery toolkit should know about this command.
**Disposition**: ELEVATE — backlog item: "Add `mempalace repair --mode from-sqlite` to librarian's recovery runbook." 1-cycle work; doc-only.

### 4. Letta Code as competitor signal (not an adoption candidate)

**Source**: github.com/letta-ai/letta-code README + Letta 0.16.7 release notes (2026-03-31).
**Finding**: Letta Code is a memory-first coding CLI, npm-distributed, mobile + Slack/Discord access, persistent agent across sessions, skill learning from trajectory. Letta server 0.16.7 raised default context to 128k, overhauled compaction, added conversation forking.
**Implication for us**: This is the most direct competitor signal. They've built the same shape we're building (persistent learning agent, skills, memory-aware compaction) on a different substrate. We need to be able to articulate **why a household substrate is better than a SaaS-hosted memory-first agent** (the answer is in project_redeploy_the_substrate and project_subsume_g_f_a_via_it_just_works — but it's not yet operator-articulable as a marketing position).
**Disposition**: WATCH — too early to act, but check again at 2026-08-14 scan. Possible memory entry: "Letta Code is the SaaS shape of our peer-native vision."

### 5. Adversarial-memory threat model (ShadowMerge / Trap of Trajectory)

**Source**: arxiv "ShadowMerge: Poisoning Attack on Graph-Based Agent Memory" (2026-05-09) + "The Trap of Trajectory: Spurious Correlations in Agentic Memory" (2026-05-10).
**Finding**: Graph-based agent memory has named attack classes (relation-channel conflicts, spurious-correlation trajectories). MemPalace KG is graph-based.
**Implication for us**: Reach-as-earned-at-authoring is our defense, but it's authoring-side. Receiver-side, we don't yet have a "this memory was poisoned" detection primitive.
**Disposition**: WATCH — no action this quarter. Re-check at 2026-08-14; if defenses literature converges, fold into project_socially_derived_security.
