# Visual-verification map — two-sprint shakeout shift (2026-06-20)

## (A) Honest framing

Almost everything in these two sprints is backend, API, data-migration, or service-layer work — not pixels. The **one genuinely-visual, net-new surface a person can see in the deployed app is the resilience-snapshot hypercard** (`<elohim-resilience-snapshot>` inside `app-protocol-omni`), reachable on protocol-content routes (`/`, `/deliver/:slug`, `/resource/:resourceId`, `/epr/:resourceId`). The only other things a person could perceive a change in are *indirect*: gated content possibly unlocking (the rebuilt PREREQUISITE access gate — no new component), and the trust-badge *not erroring* once the attestation cleanup deploys (a service-layer repoint with no mounted component today). Everything else — Weave (`/api/v1/weave`), serve-routing peer selection, the doorway membrane, federation coherence, the `attestations` table migration, CoverageRollup math — is verified at the **API/look-capture layer, not by pixels**. One fact reshapes the whole map: the deployed build is `922a11a`, which **predates both the attestation-cleanup commits and the `/api/v1/weave` route**. So the "reachable now?" column is a snapshot of the *current* deploy, not a prophecy: two surfaces FLIP after the dev-merge deploys (weave 404→live; legacy-attestations 500→gone). If the shift runs *after* the operator's dev-merge + reseed + conductor redeploy, re-probe those rows before asserting.

## (D) Do-NOT-claim-visual callouts

The shift must **not** force any of these into a visual/pixel claim — they have no render surface, and several are not even deployed:

- **Weave epic — `GET /api/v1/weave` / `build_weave_view` / operational-weave lens.** No Angular consumer of `WeaveView` (generated TS type has zero importers). On `922a11a` the route **404s — NOT DEPLOYED.** Assert at most the 404 honest-not-found shape today; re-probe after dev-merge.
- **elohim-peer-fabric (guard + score) + serve-routing peer selection.** Pure backend library + byte-fetch path. No surface of any kind. May change *which* peer serves bytes; produces no visible element.
- **Attestation-table migration (`gate_decision_attestations` + `statement_votes` → unified `attestations`; codegen `$ref` fix).** Storage/schema migration — invisible. Verify only via the unified endpoint returning `200 []` (punch-list #5).
- **Rebuilt PREREQUISITE access gate (PREREQUISITE edges + content_mastery).** Backend access-control rebuild. No new component. A person may see gated content unlock, but there is no new pixel to assert — do not manufacture a visual claim from it.
- **CoverageRollup / `coverageShortfall` 3-state.** Computed in `recursion.rs`, feeds the wire field — **rendered nowhere** (no template references it; the richer `distribution-badge.component` is unmounted). Verify only via JSON shape.
- **Trust-badge frontend repoint (`AttestationApiService.listBySubject` / `attestation:content-quality`).** Service-layer only: **no component injects the service, no template mounts a `trust-badge`.** On the *current* deploy the legacy path even 500s. Verify at the API layer (punch-list #5), and do NOT assert "trust-badge mounts cleanly" — that is risky until the cleanup arc deploys and the legacy-500 path is removed.
- **Doorway membrane (per-source rate-limit + admission) + F-COHERENCE edge fingerprint.** Operator Prometheus metrics + JSON API. No in-app pixels — verify via `/metrics` probe and the coherence endpoint (punch-list #1), never as a visual surface.

**One-line bottom line for the shift:** exactly ONE net-new visual surface (the resilience hypercard, which renders *honest-empty* today); three API surfaces give real-data assertions now (coherence, health, bootstrap-coherence); two are mounted-and-empty (resilience shape, unified attestations `[]`); one is a deploy-skew hazard (legacy attestations 500 — scope it out of look httpErrors); one is not deployed (weave 404). Populated "N of X", non-zero attestations, and weave-live all remain gated on the operator's dev-merge + reseed + conductor deploy + the `auth/me` agent_pub_key fork — none of which a deployed-app test can flip.
