When the storyteller carries an inline four-lens debate (single-agent default for routine ceremonies, ≤10 candidates, no obvious disagreement), the inline summary can lose fidelity that the story-as-authored already declared. Memory ceremony Run #2 (2026-05-14): storyteller's Wave 2 inline output mentioned only 1 MEMORIALIZE (`project_stewarded_child_identity`), but the story's frontmatter `memorializes:` block listed 3 entries (`stewarded_child_identity`, `stewardship_philosophy`, `bootstrap_to_elohim_security_gradient`). The librarian executing Wave 4 dispatched on the story-as-authored (which is the source of truth) and caught it; if the librarian had dispatched on the inline summary only, two memorializations would have silently dropped.

**Why:** Inline four-lens has structural compression. Carrying librarian/historian/cartographer/storyteller voices in one pen flattens the least-fluent lens by default. In Run #2 the compressed channel was *navigation precision*, not forensic register — the historian's voice held (storyteller re-read the historian definition pre-debate), but the summary-mode pressure compressed the storyteller's own count discipline. Reading peer voices does NOT prevent self-compression on the disposition-pen's own work.

**How to apply:**
1. **Hard rule**: any inline summary that names a disposition category (MEMORIALIZE, GRADUATE-PENDING, etc.) MUST echo the count from the underlying story-as-authored frontmatter verbatim. If story declares 3 memorializes, inline summary must say 3 — not "1 (stewarded_child_identity)" with the rest implicit.
2. **Schema hook (proposed accumulator)**: reject sprint output if `inline.memorializes.count != story.memorializes.length`. Hard precondition for Wave 4 dispatch.
3. **Wave 4 librarian dispatch pattern**: hand librarian BOTH the storyteller's inline summary AND the story-as-authored frontmatter; instruct librarian to honor the story-as-authored when they diverge (story is canonical artifact; summary is navigation).
4. **NOT a reason to escalate to TeamCreate** for routine ceremonies — TeamCreate would have produced four parallel undercounts (storyteller retro). The fix is the echo-rule, not the operating-shape.

The undercount itself is data, not failure. Captured here so Run #3+ ceremonies default to the echo discipline.
