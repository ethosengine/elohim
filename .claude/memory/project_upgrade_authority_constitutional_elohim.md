Operator course-set 2026-09-01 (rung-5 upgrade-propagation design): the protocol
stewards its own protocol. Upgrade authority is a domain of the NETWORK itself —
protocols are by nature monopoly power, and that apex power is deliberately
vested one degree removed from humans, in the elohim, at the constitutional
level. Automatic updates (Chrome-OTA-class convenience + security) are wielded
there; peers may diverge in DECLARED patterns with reconciliation pathways back,
but silent staleness is a harm class, not a freedom. Consent is exercised
through governance (heard, explained, intimate context weighed in good faith),
NOT as a per-node veto on staying current. Values-first non-negotiable.

**Refined 2026-09-03 (Holochain Evolution Epic (hApp-lineage design)).** The network is a natural
power, a true commons: an upgrade to the CORE protocol (a DNA-line crossing) is
NOT a "consent" act at all — not a household ratification, not a steward's
signature on behalf of a vote. It is a decision the elohim hold inside the
closed system, expressed as a bounded/revocable/attested Mishpat commitment
(`migrates-lineage`; the sunset is a second commitment, the only irreversible
act). I drafted the spec's §4 as "the household's deliberation completes and
matthew records the ratified commitment" — the human-in-the-loop reflex — and
the operator corrected it the same day. What humans get instead is DIVERSITY
(branches, bespoke communities) plus a COMMON LANGUAGE (lineage ·
NotarizationWitness · notarized path · bridge map) in which any upgrade or
reconciliation chain between branches is built, so a person moves through the
network's diversity only along a path notarized BEFORE they walked it. In
designs: the authorizing object is the elohim's commitment read through the
peer's own conductor; the refusal is `PathNotNotarized`, never `ConsentMissing`.
Spec: `genesis/docs/superpowers/specs/2026-09-03-holochain-evolution-epic-design.md` §4.

**Why:** the never-updating household member is exposed to security risk and
repair cost, not exercising sovereignty; a per-node update veto as apex is the
same capture vector as [[feedback_human_loop_not_terminal_authority]] — revert-
as-first-class + introspection + escalation are the safety mechanism, not
running old code.

**How to apply:** in upgrade/adoption designs, default posture = the runtime
tracks the earned canonical head automatically; adoption discipline (soak,
canary order, thresholds) is a constitutional artifact of the release ceremony,
not per-peer preference. Per-peer residual is intimate-context scheduling only.
Divergence taxonomy: lag-within-window (normal) / declared fork (legitimate,
lineage + bridge map) / silent staleness (healed, and gated out of
participation roles). Complement (same course-set): compatible branches,
low-reach runtime experiments, and A/B variants are the VSM ecology working,
not a deficit — variety lives ABOVE the compatibility envelope, unity AT it;
what works flows up through hubs and back down per context. MVP architecture
first, complete ecology later. Recorded in the arc doc
genesis/data/timeline/backlog/upgrade-propagation-p2p-design-arc.md. See
[[feedback_upgrade_propagation_north_star_wall_clock]].
