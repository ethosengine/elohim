The 2026-05-16 graph-native landing (CozoDB sled-backed projection + manifest graph extensions + Apollo Federation v2 SDL) reads in the spec as a query-substrate choice — Reading A, projection engine alongside diesel. The deeper claim is structural: **graph-native is the load-bearing primitive that lets elohim agents hold accountable positions in a shared memory of understanding between humans.**

Without it, an elohim agent's reasoning is private — it lives in model weights, isolated from the humans it's meant to serve. Whatever it produces is *opinion*. With a graph projection rooted in DHT-notarized EPRs, every position an elohim takes can be **pointed at** — same atoms the humans are walking, same couplings, same provenance, same reach. The agent can show what it knows; the human can point back; disagreement becomes locatable. That distinction — pointing at shared structure vs. asserting from private state — is the difference between **counsel and oracle**.

This is what makes the engine first-class rather than ornamental. The intelligence layer of the protocol ([[project_ubiquitous_wisdom_dissolves_chokepoint]], [[project_elohim_subagent_specialists]], [[project_elohim_as_counsel]]) is only credible at scale if every elohim on every node has the same structural ground to stand on as the humans it's accountable to. The graph is that ground.

**The dev-mode mirror.** Memory-kit + MemPalace + the four-agent team ([[reference_mempalace]], `/memory-ceremony`, `/hygiene-sweep`) are us building, for ourselves-as-developers, the same substrate elohim agents will need in production. A graph of decisions, precedents, drift signals, stories, and chronicles that any agent in our team can query and hold a position relative to. The 2026-05-17 persona-rename audit was a live instance: we couldn't have held the position "this rename has eight residual surfaces" without a graph-like scan. We held it with grep + git, because we don't yet have first-class scans in production. The graph-native engine that just landed is the *production* version of the same primitive — same operation, same audit, but at protocol gain.

So this dovetails with the alpha-to-omega framing from [[project_genesis_is_protocol_interpretability_layer]]: **the memory-kit we use to keep ourselves coherent is what the graph engine becomes when it graduates.** Dev tooling and production primitive are the same thing at different gain levels. Memory-kit drives a librarian; in production, elohim agents query the same graph for the same coherence questions, just on EPRs instead of markdown frontmatter.

**Why:** This reframes "more graph features later" as urgent rather than nice-to-have. Every elohim role the protocol promises — defender, advocate, steward, gate-discerner, recovery witness — needs an accountability surface. Without it, those roles become "an LLM with a manifesto," which is exactly what the protocol exists to refuse ([[project_intelligence_revolution_scales_to_humans]], [[project_redeploy_the_substrate]]). The graph engine is where accountability gets its physical body.

**How to apply:** (1) When designing any new elohim capability (judgment, recommendation, gate decision, attestation), ask first: *what graph does this agent point at when challenged?* If the answer is "model weights" or "private state," the capability isn't ready — it needs a graph projection it can reason from and a query primitive a human can also run. (2) When prioritizing graph-native follow-on work (vector pipeline, additional view builders, lamad/qahal/shefa extensions), favor work that lets agents make positions pointable. Pointable beats inferable. (3) When adding any new agent role, design the dev-mode rehearsal (memory-kit queries, MemPalace surfaces) at the same time as the production primitive — they're the same operation. (4) Recognize when grep+filesystem coherence work is a stand-in for a missing graph primitive; surface it as "this would be a one-line query against the graph in production" so the gap is visible. (5) Trust as efficiency signal ([[project_trust_as_efficiency_signal]]) compounds: shared-graph reasoning is cheaper to distribute *and* more trustworthy than oracle-shaped reasoning, so the substrate's economics already favor this design.
