Operator correction (2026-07-23, discipline-1 slice): I framed the escalation-ladder charter as awaiting "the operator's ceiling act" — a solo stamp. Wrong shape. **The act is reserved for US**: until p2p distributes the fabric, the deliberating community is operator+agents working the tree, and the working conversation IS the deliberation chamber.

**Why:** The repo already runs the reach epic on itself — the branch ladder is the repo's reach axis (`shift/*` = self, `dev` = community via integrator-accepted merge, `main` = commons via release review), and memory already records a push as "a reach-earned attestation at the deterministic floor." So a governance rule is a *claim*; deliberation is *peer review*; ratification is *canon conferred by a governance act* — and the merge acceptance IS that act (the CanonizationRef of repo governance). A rule on a shift branch is structurally pending; hand-toggled "pending" strings and solo-authority stamps both rebuild the single-authority shape the protocol dismantles. Part of accepting a merge is accepting the rules we govern ourselves by.

**How to apply:** Provenance fields record deliberation, not authority-species: `established_by: deliberated-<date>-<participants>` (validators accept `deliberated-*` + legacy `operator-*`; see `epr:validator-escalation-ladder` in both runtimes). When designing ratification/approval flows, route through the peer-acceptance event that already exists (merge, witnessed review) rather than inventing a stamp; name the trajectory: the shape stays identical as the peer set grows from two-party to qahal.
