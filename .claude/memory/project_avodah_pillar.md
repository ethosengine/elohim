Avodah is a **reference implementation** that demonstrates the elohim-protocol's *own* process/pipeline — "protocol as process." It's how work/contribution/service flows are modeled *as protocol participants*, not a separate domain dimension. Exists at `app/elohim-app/src/app/avodah/`.

**Why:** User explicitly corrected that avodah is "not exactly a pillar but just another reference implementation that facilitates/demonstrates the elohim-protocol process/pipeline." The phrase "protocol as process" frames avodah as meta-level — the protocol demonstrating its own work flow as a protocol participant.

**How to apply:**
- **True domain pillars:** imagodei (identity), lamad (story/learning), shefa (value/economy), mishpat (governance), qahal (community). These define the dimensions that must be co-present for capture-resistance.
- **Reference implementations (facilitators/demonstrators):** avodah (protocol-as-process, work/contribution pipeline), doorway (web2 projection). These show HOW protocol operations flow, not WHAT dimensions matter.
- When listing "batteries-included" reference subgraphs shipped with elohim-core, separate the pillar-reference subgraphs (one per domain dimension) from the process-reference subgraphs (avodah, doorway).
- Do not include avodah in pillar tables or capture-resistance constraints. Do include it when showing how work/contribution flows are themselves first-class protocol citizens.
