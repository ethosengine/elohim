Operator's north-star (2026-07-09) for how the earned-authority / canonical-HEAD model plays out in the live network — the vision the [[project_versioned_entity_head_is_declared_dependency]] + notary-authority work is bootstrapping toward. Not in the repo; design-shaping.

- **Below the commons head, peers naturally diverge / fork / merge / compete.** Multiple valid authorings coexisting is the expected steady state, not a bug (the "penicillin" reframe). Convergence on ONE canonical head is an *earned* authority act, not a lock — never first-writer-wins, which is only a dev-time scaffold.
- **Earned reach scales with the artifact's stakes.** For high-stakes artifacts it "starts feeling like a GitHub PR ceremony" — but the review payload is **story + value (REA) + governance aggregated and synthesized** (prior art the operator names: polis · monarch-app · loomio · slack · meta-hylo · open-collective · patreon), debated and **continuously affirmed by councils of Elohim (hylonic/holonic sociocracy)**. Elohim agents are the *tenders* of these socially-derived grants — grantors of reach who help humans help themselves — never bestowers of authority by fiat.
- **The whole thing sits on the resilient p2p blobstore (no Google/AWS datacenter)** — custody/salvage N-way replication — so "people just don't worry about it anymore." Resilience is the floor that makes the governance ceremony trustworthy.

Design consequence: authority = earned attestations → reach promoted amber→green at the commons threshold → canonical HEAD elected + adopted cross-peer (verified against the notary witness). No earned attestations ⇒ the authoring stays **private/limited-reach**.
