Canon: `genesis/docs/content/elohim-protocol/lamad.md` §1 Territory vs. Journey (content nodes are
reusable territory; a path step is a journey moment referencing it) and its meaning maps
(knowledge / love / self). Operator restated it 2026-09-27 (re-authoring the FCT path): paths are
hoped to become **dynamically constructed** — personalized learning inherits the relationships, reach and social shape of
walking the graph of meaning between EPRs, and each person's elohim customizes the path so
learning, discovery and attestation work like love maps (knowing a person's inner world).

Reach is part of the walk's shape. FCT is a **commons** resource by the developers' own
declaration and judgment of its suitability for the commons; the seeded love-map paths
(`love-map-matthew-jessica`, `love-map-adam-eve`) are **intimate** reach, modelling a
household's private love map. A commons recomposition or publish tool must never touch or
raise intimate-reach content.

The operator's framing: today's static path files are **a concession so we can model the
primitives while the architecture matures**, not the target form.

**Why:** a hand-authored path is a projection, not the container of meaning. If structure lives
only in `paths/*.json` chapters/sections, a future composer has nothing to walk.

**How to apply:** when authoring or recomposing a path, put the structure on the atoms —
typed relationships (anchor/supporting verse, story, practice lane, callback, refrain concept),
reach, stewardship — so the authored path is just the canonical walk. Never orphan a
cross-linked atom from a path it anchors (e.g. `evolution-of-trust`, which many a2o features
fixture). Keep seeded ids stable; upgrade content in place rather than minting new slugs.
