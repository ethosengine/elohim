The Elohim identity ontology (imagodei pillar) treats a human's identity as imago dei — an inviolable right **backstopped by institutional/social expression**, not a self-asserted crypto primitive. The architect has repeatedly had to fight "self-sovereign / true data sovereignty" framing from leaking into the substrate vocabulary. AI coding agents default to the silicon-crypto sovereignty ontology (overrepresented in training data) and it slips past the design gates specifically at **tier-naming**: an apex tier called "self-sovereign" reads as a neutral capability level ("more keys → more autonomy → higher") rather than the ontological claim it actually is, so it sails through review that would catch a load-bearing assertion. **Resolved 2026-07-15 (landed on dev @35e56d1ae).** The corrected apex lexicon is now decided: **"community-grounded autonomy"** (architect's call). The known-live drift was swept — `manifesto.md:158` (data-sovereignty implementation goal → community-backstopped stewardship), `hardware-spec.md` ("Progressive Sovereignty"/"Four Stages of Digital Sovereignty" + "Self-sovereign" tier cells + "true data sovereignty" → Progressive Participation / community-grounded autonomy / data stewardship), and `imagodei/CLAUDE.md` (agency-tier labels reframed; the deprecated `'self-sovereign'` TS code-literal preserved + annotated so the doc stays true to the contract — the literal's removal is a separate identity.model.ts deprecation migration).

**Why:** Sovereignty-without-community is illusory; real freedom/agency/security come from community and institutions backstopping the individual. Unqualified self-sovereignty also can't model the whole human life — children, IDD, seniors, legal wards — where the right is exercised *with/through others* (the repo's own IDD design says "supported decision-making, NOT substituted judgment"). Hardened cryptographic sovereignty is extended only in rare, justified cases (e.g. targeted dissidents under state duress) — the exception, never the apex default. This is the architect's core differentiator vs. the crypto/"sovereignty" space, and the pitch to governance-minded collaborators (e.g. Ethelo) leans on it.

**How to apply:** Never introduce or celebrate "self-sovereign" / "sovereignty" as the positive top of an identity/agency gradient. Frame the high-autonomy tier as community-grounded (e.g. node-stewardship standing) and keep sovereignty subordinated to community-adjudicated governance. Quoting sovereignty as an *adversary frame* (the thing being resisted) is fine; asserting it as the protocol's own apex value is the drift to catch. Corrected apex lexicon = **community-grounded autonomy** (settled 2026-07-15).
