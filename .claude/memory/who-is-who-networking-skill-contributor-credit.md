A planned **"networking / who's-who" skill** — a *social/attribution* lens, distinct from the builder trio ([[atlas-grounding]] · concept-mapping · app-port) and the evaluator lenses (product/VC/philanthropist). It consults the contributor network to know **who inspired this work** — the real people and open-source libraries behind it.

**Why:** so the work can credit its lineage, and so the protocol's own onboarding (app-port) names the real creators it re-composes.

**The machinery is ALREADY WIRED** (grounded /btw 2026-06-21 → `genesis/docs/content/elohim-protocol/history/2026-06-21-contributor-presence-whoswho-grounding.md`). `ContributorPresence`'s own doc comment is *"recognition before registration — for citing authors, speakers, and contributors who aren't yet on the network."* It is a DHT entry type (imagodei + content_store), projects to storage (`ContributorPresenceView`, `db/contributor_presences.rs`), and carries the whole flow as fields: `establishing_content_ids` + the `derived_from`/`source_of` relationship (the inspiration link — **not** net-new), `recognition_by_content`/`citation_count`/`affinity_total` (accrual *in the contributor's absence*), and `claim_recognition_transferred_value` (value transferred when a real person claims). REA distribution (`economic_event_service`, `reach_earning.rs`) carries the credit. **So the skill is NOT gated on building the machinery** — only on the items below.

**Ethical posture (operator's model): ALWAYS account; opt-OUT → commons.** Presences mint value *unconditionally* in the contributor's absence — you can't consent the planet, and a true commons requires accounting everyone (the anti-Pirate-Bay / Bookshop.org / Kiva / Bandcamp / fair-trade design). Two terminal flows: **claim** (real person receives accrued value) or **opt-out** (accrued value is **redirected to the commons**, never deleted).

**The one genuinely net-new piece:** `presence_state` {unclaimed, stewarded, claimed} needs an **opted-out** state + a wired **commons-redirect** (an REA event distributing accrued value to a commons pool).

**Prerequisites, in order:** (1) the opt-out→commons state + REA redirect; (2) cohort-1 library seeding (Khan Academy/Perseus, Holochain, libp2p, iroh, Automerge, ValueFlows/hREA [Foster & Haugen], REA/McCarthy, Unyt, gitoxide, Eclipse Che — bounded, safe); (3) cohort-2 named individuals (Torvalds + the authors behind each library), same accounting, claims **invited** via the Canteen/creator-payments channel ([[project_canteen_outreach_thread]]) — an invite, NOT a precondition for accounting.

**Ties:** `app-port` produces the attribution surface (porting prior art names its real creators/libraries → inspired-by contributors via `derived_from`). Reach-earned-at-authoring + the REA `EconomicEvent` credit leg carry the value. `ContributorPresence` lives in the imagodei domain.

Key design decisions: **standing gradient, not a real/fixture wall** — a non-notarized seed-layer `standing` field {inspirational · prior-art · interlocutor · operator-persona}; the hard edge sits on the irreversible *consequence* (value receipt / claim-invite), gated by a confirmable fact (real channel / claimed agent key), NOT on the person. Layer-1 witnessing accrues for all standings. **"Init allocation" is on-grain = seeded citations (source_of/establishingContentIds) + optional StewardshipAllocation, NOT a fiat recognition balance** (the create path hard-zeros recognition; the TS seeder's recognitionScore field is dead). Reach is content-scoped, never presence-scoped. **Collectives are presences too** (`presenceType: organization`) — the Google-Maps-attractor = recognition-before-registration as a growth mechanism.
