The frontmatter on `genesis/data/humans/terrance-tutor.md` — `id`, `displayName`, `category`, `profileReach`, `bio`, `affinities`, `communities`, `attestations` — is already an EPR-shaped representation of personhood. The same shape that will, in production, be a notarized atom on the DHT, projected into the CozoDB graph as `epr_node`, served through a doorway, and rendered into an Angular surface. Genesis isn't *describing* the protocol; **genesis is the protocol's human-readable surface running in dev-mode**.

That makes genesis stories the **interpretability layer** of the Elohim Protocol — the surface where complexity collapses into a name a grandmother can recognize. The composition is: persona markdown → JSON simulacrum → seeded into DHT → projected into graph → served as view → rendered as Angular component → seen by a child on a tablet who reads "Terrance" and recognizes their tutor. Getting that chain coherent for a handful of personas is the load-bearing rehearsal for what the protocol promises at scale.

The alpha-to-omega arc: **genesis artifacts will graduate into views upon the protocol they describe.** They don't get thrown away when the system goes live. The markdown source becomes the EPR; the EPR becomes the graph node; the graph node becomes the view; the view is rendered back to the human whose story it captures. The artifact participates in the whole process from alpha (dev-time stand-in) to omega (production projection), holding the same identity throughout. Dev process and production are the same process at different gain levels.

**Why:** This frames every genesis-coherence problem (the 2026-05-17 timothy→terrance audit, gherkin scenario fixes, account-package regeneration drift, chronicle factual claims) as **protocol-quality work, not housekeeping**. A persona rename touching eight surfaces in dev is the same failure mode a real-world contributor name change will touch in a real qahal. The chronicle's "zero stale references" falsehood is the same shape as a falsehood about a contributor's reach in production. We can't ask grandmothers to trust a substrate we can't keep coherent for ourselves with a handful of personas.

**How to apply:** When working on genesis, treat the artifact as a live instance of the protocol, not a fixture. (1) Frontmatter changes are EPR-schema changes — write the schema first ([[feedback_schema_first_ioc]]); the markdown conforms. (2) Identity renames cascade through five surface classes ([[feedback_persona_rename_completeness_checklist]]); audit per-surface, never trust "we updated the source." (3) Stories are first-class graph nodes with `delivery_status` lifecycle ([[feedback_story_delivery_status_axis]]); they will eventually be EPRs. (4) When designing new content surfaces (qahal directories, shefa reciprocity views, lamad paths), look at what genesis already declares and design BOTH the production projection AND the dev rehearsal at the same time — they're the same thing at different gain. (5) Chronicles are stories about ourselves in the same graph; falsehoods there have the same weight as falsehoods anywhere else ([[feedback_inline_summary_must_echo_frontmatter]]).
