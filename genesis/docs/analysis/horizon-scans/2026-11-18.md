# Horizon scan — 2026-11-18

The full reading, with its grounding in the manifesto and the EPR, is the research note [epr:memorilla-claude-dreaming-cross-pollination-2026-11-18](../../../research/memorilla-claude-dreaming-cross-pollination-2026-11-18.md). This scan carries only what changes for the memory team.

## Summary

Anthropic's dreaming now exists in three forms: a Dreams API that writes a reviewable copy, a cookbook workflow built from small-model readers, and an auto-dream inside Claude Code that edits the memory directory in place behind a server flag. All three treat consolidation as cleanup, which our living-memory canon names as the mistake; the usable lessons are the schedule, the cheap readers and the copy. The Claude Code client also contains `team/` memory and server-synced project memory, the first native shared-memory channels, held by a server under organisation policy. Memorilla, a learned latent memory from Stanford, is left as released because its output cannot be shown, cited or recognised; its split between a shareable reader and a per-person collection is worth study.

## Horizon delta — what's new since 2026-09-06

**1. Auto-dream is in our client, and can be settled by one setting.**
- **Source**: installed Claude Code 2.1.327, 2026-11-18. No official page documents it.
- **Finding**: a setting `autoDreamEnabled` ("overrides the server-side default"), a gate of 24 hours and 5 sessions, and a four-phase prompt that deletes, merges and re-indexes memory files in place. The 2026-09-06 scan could only mark this unverified.
- **Implication for us**: our memory directory is git-tracked and its index is generated. An in-place dream would hand-edit a governed projection with no `supersedes:` edge and no Steward's verdict.
- **Disposition**: ELEVATE (set it to `false`; a settings change for the steward).

**2. The Dreams API writes a copy; the cookbook shows the cost shape.**
- **Source**: platform docs and cookbook, 2026-11-18.
- **Finding**: the docs state the input store is left unmodified; 1 to 100 sessions per dream; the dream is a watchable session. The cookbook uses one small-model reader per transcript and one organizer, about $8 for fifty long transcripts, nightly by cron.
- **Implication for us**: this is the proposal-only `/dream` our 2026-05-10 lifecycle design specified and has not built, at a fraction of the cost of four top-tier lenses.
- **Disposition**: ELEVATE.

**3. Native shared memory exists: `team/` and synced project memory.**
- **Source**: installed binary; Projects documentation.
- **Finding**: a `team/` subdirectory shared across the people working on a repository; memory stores synced to a server with organisation policy, write opt-in and read-only mounts, where the server's copy overwrites local edits. The dream prompt tells the dreamer not to promote personal memory into `team/`; that is "a deliberate choice the user makes".
- **Implication for us**: the same rule we hold (widening is a deliberate act through the reach gate), with one party holding bytes, keys and the tie to the person together. On our ground the network may hold the bytes while the person holds the join.
- **Disposition**: WATCH the feature; ELEVATE the rule.

**4. Memory stores mount with an access mode, up to eight per session.**
- **Source**: platform memory docs.
- **Finding**: `read_only` or `read_write`, enforced by the filesystem; every write is a version attributed to its session; versions kept 30 days.
- **Implication for us**: a session could declare its memory mounts by ring and access mode, as it declares its write set.
- **Disposition**: WATCH.

**5. Memorilla: latent memory for frozen models.**
- **Source**: repository at `6864db7`, read in source.
- **Finding**: documents embedded once; sixteen question-conditioned vectors injected into the decoder's input embeddings; no consolidation, no forgetting; per-document attribution computed and discarded. Trained with reward as agent memory, it lifts TextWorld success from 18.6% to 24.2% on a small sample.
- **Implication for us**: unusable with hosted models, and without attribution it cannot meet the EPR's three legs or be shown to the person it describes. Two ideas worth keeping: memories that record whether acting on them helped, and the split between a reader that could be a commons artifact and a collection that stays with its person.
- **Disposition**: SKIP as released; WATCH for attribution; study the split.

## Already-aligned

- Other authors' entries are pruned conservatively (ours: a non-curator Steward's verdict).
- The index is a projection, kept under a size limit, and holds pointers in place of content.
- A session's memory writes are attributed.
- Memories are reconciled against `CLAUDE.md`, with the checked-in file as the maintained source.
- Transcripts are treated as data, not as instructions.

## Elevation candidates

1. **Decide the native auto-dream deliberately.** This scan recommended switching it off. The steward ruled on 2026-11-18 to leave it on and learn from it; each dream then arrives as a working-tree diff to read.
2. **Build the thin `/dream`**: scheduled, small readers, output as a branch and a diff, each proposal recorded as a consolidation event on the valueflow, recall journeys run before and after. Canon source: the living-memory epic's "Consolidation Is Judgment, Not Janitorial Work".
3. **Give each memory entry its own reach**, so widening is a compose through the reach gate, and keep reach separate from custody and from the join (who may tie entries to a person, from where, for what).
5. **Design the join record and the path to Memorilla's usefulness** (research note §1 and §4.2): a commons-stewarded reader, person-held joins over encrypted custody, attribution surfaced.
4. **Name a habit for the sibling memory channel** so the collective-memory seed stops waiting.

## Substrate / dependency changes

- **Claude Code**: auto-dream, `team/` memory and synced project memory are present in 2.1.327 and absent from the documentation. Their behaviour may change without notice. The documented position is unchanged: auto memory is machine-local.
- **Managed Agents**: memory-store calls now use the `agent-memory-2026-07-22` header; dreams need `dreaming-2026-04-21`. We do not use either API.
- **MemPalace**: not checked this scan.
