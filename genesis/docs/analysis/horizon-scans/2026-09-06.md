# A — Horizon delta (cut to what informs B)

**1. Consolidation is budget-conditional — and we are on the paying side of the crossover.** *Retain or Consolidate?* ([arXiv 2607.17545](https://arxiv.org/abs/2607.17545), 2026-07-20) benchmarks Merge / Abstract / Rewrite against plain retention: "Neither strategy is universally preferable" — consolidation "improves accuracy by up to 48% under tight budgets" on LongMemEval, while retention wins under loose ones, and cross-note abstraction beats local rewriting when compression is forced. This is the direct answer to "not convinced of its effectiveness": effectiveness is a function of whether the store fits. Ours does not (see B).

**2. First-party "dreaming" is real, and its shape is the review-then-adopt gate we already run.** [Dreams](https://platform.claude.com/docs/en/managed-agents/dreams) (research preview; beta headers `managed-agents-2026-04-01` + `dreaming-2026-04-21`, retrieved 2026-09-06): an async job over one memory store × 1–100 session transcripts emitting a **new** store — "The input store is never modified, so you can review the output and discard it." Trigger is an explicit API call, not a schedule. Cost is metered on the resource (`usage.input_tokens`) and "scales roughly linearly with the number and length of input sessions"; the doc's own advice is "Start with a small batch of sessions and scale up once you're satisfied with the curation quality." Forget/keep = "duplicates merged, stale or contradicted entries replaced with the latest value," steerable by a ≤4,096-char `instructions` field. **No measure of whether it helped is offered** — human review of the output store is the check. (Third-party reports of an "Auto Dream" in Claude Code — implicator.ai, claudefa.st — are **UNVERIFIED**; no first-party doc found.) The [memory tool doc](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) separately sanctions access-based forgetting: "Periodically delete memory files that haven't been accessed in a long time."

**3. Rewriting is itself a hazard.** *Manufactured Confidence* ([arXiv 2606.29279](https://arxiv.org/abs/2606.29279)): "this rewriting manufactures confidence: a casual, hedged remark becomes a confident, dated assertion the agent then obeys like a verified fact"; passive `unverified` tags are ignored; the fix is to "keep the tentative phrasing rather than upgrade it… a single load-bearing memory is the hazard." Our storyteller's pen does exactly this rewrite.

**4. Cost bounding is incremental everywhere.** Mem0 ([2504.19413](https://arxiv.org/abs/2504.19413)) extracts per turn against same-identifier neighbours, ">90% token cost savings, 91% lower p95 latency" vs full context; Graphiti ([2501.13956](https://arxiv.org/abs/2501.13956)) ingests discrete episodes and never deletes — contradictions are handled by temporal edge invalidation; A-MEM ([2502.12110](https://arxiv.org/abs/2502.12110)) evolves a neighbourhood, not the store; LightMem ([2510.18866](https://arxiv.org/abs/2510.18866)) decouples the offline update for "up to 38x" token reduction. Letta's sleep-time compute ([2504.13171](https://arxiv.org/abs/2504.13171)) reports "~5x" less test-time compute and "2.5x" lower cost per query — **but only where queries are predictable from the context**.

**5. The field has no contradiction/staleness metric.** Closest are MemoryAgentBench's Conflict Resolution task and Graphiti's invalidation mechanism. Our Phase-0 stale-record is already an instrument the field lacks — it is unmeasured, not unavailable.

# B — Refinement plan: keep the memory HEAD fresh

**Measured today** (all figures reproducible): `.claude/memory/MEMORY.md` = **30,613 B / 117 index rows** against the 24.4 KB harness load cap (`placement-audit.py:98` `MEMORY_MD_BUDGET = 24000`) → **22 index rows (19%) never enter any session's context**. The 100 unindexed files are *all* deliberate `index: false` folded members — 0 orphans, 0 missing frontmatter, so the umbrella-fold machinery works; the head is simply over budget. 19 descriptions exceed the 200-char cap (`.claude/memory-kit/memory-index-drift.json`); trimming all to the 160-char target recovers ~2.15 KB — **a third** of the 6.6 KB needed. The rest (~17 rows at 260 B avg) is population work. Nothing measures post-ceremony effect: chronicles carry GREEN/YELLOW/RED verdicts but no cost, and no script diffs the 15 dated `substrate-currency-audit.json` snapshots.

They should not be one pass — but they share Phase 0/1 triage and all four agents, so a second skill is waste. **Owner: storyteller** (already the admission gate; "You nominate; the librarian ingests", `storyteller.md:31`). No new agent.
