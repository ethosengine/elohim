# Substrate Readiness Assessment: Native Recursive Signal Aggregation at Commons-Compute Scale

Synthesis of six verified investigation briefs (DHT/recursion · transport · storage/projection · scaling-case-A hubless · scaling-case-B hub-not-doorway · commons-target yardstick), each adversarially re-verified against primary source. This assessment aggregates those findings; it does not re-investigate. Every `file:line` traces to a brief.

## 1. Verdict

**PARTIAL — but the honest read is "the foundation tier is live; the aggregation tier runs nowhere."** The substrate has a genuine, well-engineered, *single-level / intent / household-tier* layer that is wired end-to-end and serving traffic: the `CoverageRollup` engine is consumed on a live HTTP read path, the generic REA commitment pipeline authors `replicates-commons` through the conductor to the DHT, libp2p peers federate cluster/topology/inventory views over a hostname-free peerId path, and per-node compute-as-pod surfaces feed doorway SSR. **But every property that makes aggregation *recursive* and *global* — descent traversal of aggregate-of-aggregates, a transport that carries rollup/REA-aggregate payloads across DHTs, and the realized (observed) compute value-flow that turns intent into accounted flow — is BUILT-UNCONSUMED (tests only), ABSENT (no code), or a deliberately-gated fork (SPEC-ONLY).** No rollup has ever crossed a hub boundary in production. **The single biggest blocker is R2: there is no aggregate-carrier transport.** The view-federation wire carries only flat metadata views (Cluster/PeerTopology/ProjectionInventory, 256 KiB, "~2 devices") and verifies structurally only; the consilience path that would let peers exchange and witness rollups (`witness_quorum` / `CoverageRollupAttestation`) is a fork the spec says "do NOT take preemptively"; and alpha is one DHT / one swarm, so even a coded carrier could not be exercised today without `shem`. R1-recursive is the *cheapest* keystone (engine built, N=2 transitive composition proven in test, just unwired), but R2 is the deepest — it blocks the global tier even if R1 and R4 were finished.

## 3. Scaling-Case Verdicts

### Case A — homes with NO always-on node (hubless)
**First-class today for the signal/economic layer; NOT first-class for self-maintaining byte durability.** A hubless home does *not* need to run a hub to contribute: notarized signals persist via the conductor→DHT path independent of any local rollup, and the live chain provide-loop (`main.rs:1314`) → `CommitmentCommitted` signal → active `rea_commitments` provide row → resilience fold (`household_resilience.rs:155-217`) is end-to-end wired and reachable. Critically, `hub_id` in the folds derives from `humans.household_id` (the social collective), **not** from running hub hardware — so the rollup gates on shard-placement diversity, not on owning a hub. Content bytes *can* survive offline via a real proactive shard-push to peer custodians who need not be hubs (R5a). **The missing piece is two-fold:** (1) autonomous self-placement — the durable "place my content at RS(N,K) across N households and maintain the floor" layer is `src/tier/`, which does not exist (TierController/drivers SPEC-ONLY; `replicates-dwelling` writer test-only); today byte durability happens only if distribution was externally triggered and `peer_selection` succeeded. (2) The aggregation join `provider → humans.agent_pub_key → household_id` silently empties to all-zeros under identity incoherence (transport-mode `self_cid` ≠ seeded `agent_cid`, or NULL `agent_pub_key`) — a historically-breaking fragility, and the general transport-id resolver is specced-but-blocked.

### Case B — always-on node that will NOT be a doorway operator (hub-not-doorway)
**First-class today as a non-doorway peer that federates views; NOT first-class for aggregation.** This is the *live operational default*, not a future state: every per-human node is a 0-ingress libp2p peer that *consumes* a doorway's bootstrap/signal but is not one — the deploy model only ships this shape (the doorway is its own deployment; `nodeTypes` never encode doorway-operator-ness). Such a node already federates cluster-view, peer-topology, and REA projection-inventory over a hostname-free peerId path today — writer (`run_sweep` spawned `main.rs:3046`), responder (`mod.rs:5007-5052` reads local SQL + sends response), and reader (`Federator::query` on live routes) all verified. **The missing piece is two-fold:** (1) the cross-peer **aggregate-tick scheduler** is BUILT-UNCONSUMED (`aggregate_and_emit` test-only; tick "explicitly deferred") — the node can serve a view of its own rows when asked, but nothing drives a recurring cross-peer commons rollup. (2) There is **no typed Hub role** — no `trait Hub`/DwellingHub/CollectiveHub, no "hubbiness dial," no elohim-operator orchestration; hub-ness is implicit (an always-on peer with `ENABLE_P2P=true`), not a governed declared role. Commons-compute contribution without a doorway is also unreachable: `delegates-compute` is a parsed-but-unexecuted record (R3b).

## 4. Prioritized Gap Work-List (by leverage)

**[code-now] (buildable on household-nodes today — high leverage, finish what's built):**
1. **Convert the operational-weave lens from hand-written `sum()` to `CoverageRollup` descent** (Weave #1, spec `2026-06-20-weave-epic-arc-design.md:78-84`). *The keystone.* The recursion engine + N=2 transitive composition are built and tested; this is the first live multi-level caller. Highest leverage, lowest cost — it unblocks R1b and gives R2 something real to carry. **[built-unconsumed → cheapest path to recursion]**
2. **Drive the cross-peer aggregate-tick scheduler** (`services/aggregator.rs::aggregate_and_emit`, today test-only; `concentration_service` "explicitly deferred"). Turns Case-B nodes from serve-on-request into recurring commons rollup contributors. **[built-unconsumed]**
3. **Wire a live `replicates-dwelling` writer** (`replicates_dwelling_service.rs:90`, today test-only) — an HTTP route or reconcile loop authoring the cross-dwelling-redundancy commitment. Closes the first rung of Case-A self-placement without the full TierController. **[built-unconsumed]**
4. **Repair / harden the identity-coherence join** `provider → agent_pub_key → household_id` (Case-A rollup all-zeros failure). Currently the single point that empties the whole aggregation; an integrity guard + the transport-id→`agent_cid` resolver is the durability win.

**[needs-substrate/operator] (blocked on capability or operator-owned infra):**
5. **R2 cross-DHT aggregate transport** — define the rollup/REA-aggregate payload type for the view-fed wire, then witnessed exchange. Cross-region exercise needs `shem` (cluster capability, not default); a single-DHT mesh can prototype the payload but cannot test the boundary crossing. *This is the deepest blocker — sequence the payload-type work [code-now] but the boundary-crossing validation is substrate-gated.*
6. **R5b offline-replication fan-out guarantee** — blocked in practice on the still-OPEN conductor OOM leak (a healthy multi-peer mesh is required for real fan-out). Operator/RCA-owned.
7. **`delegates-compute` live authority path (Z.D)** — replace the deploy `ADMIN_KEY` with a `delegates-compute`-authored authority; needs the deploy-authority design landed plus an executor. **[built-unconsumed record + design-status execution]**

**[design-first] (not buildable until the design fork is taken):**
8. **R4 realized compute-fulfillment EconomicEvent** — no schema/action/emitter exists; design the discriminator before any code. The structural prerequisite for "aggregated valueflows," and currently ABSENT.
9. **R6 `KeyEnvelope` / private-replica encryption** — new DHT entry + X25519 reader-key substrate; weave Wave C, blocked on the encryption design + conductor-leak fix.
10. **R8b limitarian governor + Dunbar detection** — propose→vote→tally ratification of constitutional rates; SPEC-ONLY.

**Do NOT do now:** `CoverageRollupAttestation` (the witnessed-rollup DHT entry). The recursive-architecture spec explicitly gates it: "GATED behind a recompute-cost probe; do NOT take preemptively" (`…recursive-architecture-design.md:303`). It is a fork to take only if Category-C recompute provably can't fan out at scale — not a do-now item.

## 5. Disagreements & Uncertainties

- **The one genuine cross-brief tension: is the weave-doc's "`CoverageRollup` built-but-unconsumed" label accurate or stale?** Brief 1 (DHT) reads the spec as *accurate*; Brief 6 (Target) reads it as *stale on this branch*. **Both are right at different tiers, and this is the resolution:** *flat/single-level* consumption is now genuinely live (the spec label is stale for R1a — there ARE live shefa callers via `coverage.rs`), while *recursive/multi-level* consumption is still unbuilt (the label remains accurate for R1b). The split-row table encodes exactly this.
- **Identity-coherence join fragility (uncertain reliability, not a build gap).** The Case-A/Case-B aggregation folds are LIVE-WIRED but their *accuracy* rests on a `provider → humans.agent_pub_key → household_id` join that has historically emptied to all-zeros (documented resilience-card bug; provide-loop goes dormant on NULL `agent_pub_key`, `main.rs:473,502`). LIVE-WIRED here means "the code path runs," not "it reads non-zero in every deployment."
- **R2 is untestable today even if coded.** Alpha is one DHT / one libp2p swarm (6 household peers); there is no second DHT to aggregate across. Cross-region aggregation is gated on `shem`, which is a developer-flippable capability but not on by default. So R2's "ABSENT" is reinforced by topology, not only by code absence — a coded carrier could not be exercised on the current mesh.
- **R5 fan-out is blocked by the conductor OOM leak (still OPEN).** The shard-push write path is live, but a real multi-peer fan-out is gated on mesh health, which the unresolved native-heap conductor leak degrades. Brief 4 hedges R5's offline guarantee to "BUILT-UNCONSUMED-in-practice" for this reason.
- **One brief over-optimism, corrected:** the transport brief's "iroh/libp2p dual-publish = LIVE-WIRED" was downgraded by its own verifier to BUILT-UNCONSUMED — `p2p-iroh` is non-default and the dual-publish block is compiled out of the prod binary (a parity-harness artifact). The Case-B iroh `TRANSPORT_BACKEND` evidence was also corrected: a legacy manifest sets `dual-stack` but the code reads `ELOHIM_TRANSPORT_BACKEND` (name mismatch) on a superseded StatefulSet — inert either way. Neither correction changes a verdict; both reinforce "iroh hub-to-hub does not ship."
- **No LIVE-WIRED label in any brief survived as wrong** under adversarial verification once reachability (default features + Dockerfile plain build) was confirmed for the `graph-native` reader path. The foundation tier is real; the disagreements are entirely about the apex tier and reliability-in-deployment, not about whether the wired paths exist.
