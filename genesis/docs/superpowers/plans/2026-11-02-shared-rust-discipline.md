# Shared Rust discipline

Elohim offers its Rust discipline; Brit independently adopts an exact addressed
version with explicit local adaptations. Shared ownership cannot substitute for
scope authorization. Local, network and real-adoption evidence are separate.
No policy-impact simulation platform is required for this low-stakes adoption.

## Required delivery stations

- [ ] SRD-1: Portable content and standing separation, valid CID codecs, preserved legacy pins, and offline artifact verification.
- [ ] SRD-2: Local addressed-policy resolution and isolated two-space ceremony; no implicit upgrade or execution on discovery.
- [ ] SRD-3: Authorized network policy binding, witnessing, remote read-back, revocation and restart/reconnect proof.
- [ ] SRD-4: Independent agent encounter produces a useful scoped trial and transition with disagreement retained.
- [ ] SRD-5: Real Brit adoption projects the guide and wires local, committed pre-push and required CI checks.

## Acceptance contract

Shared core semantics; scope, rollout and upstream compatibility may vary explicitly.
New meanings require successor artifacts. Mandatory unavailable rules never silently
disappear. Private deliberations stay local. Discovery cannot confer authority or run
received executables. Source, baseline, checker, parameters and policy key evidence.
Two isolated repositories must continue checking offline; either space may decline,
retain a version or propose an adaptation without altering the other's adoption.
Network completion requires a receiving peer's independent read-back, not merely the
author's signal or projection. Fixture signatures never stand for real acceptance.

## Grounded frontier

The existing canon lift passes freshness (42 atoms / 31 heads), but hashes JSON as
DAG-CBOR and includes standing in the hashed policy row. Preserve that legacy format
for historical verification; introduce a versioned portable representation. Native
policy evaluation currently reads a local registry. Mishpat implements author-lens,
but not binds-policy. Its Commitment primitive returns distinct entry/action hashes.
Reusing that primitive is conditional on structurally enforcing scope authority;
payload shape validation alone is insufficient. No new integrity type or HTTP route
is assumed. A full delivery cannot be declared from local fixtures alone.

## Steward-authorized micro council

The steward's 2026-11-02 direction is to exercise the encounter through separately
grounded agents, each representing a repository and its stewards. This case has one
human steward and two repository seats. Imagodei linkage is unresolved; the explicit
session instruction supplies local delegation only. Two seats do not constitute two
humans, independent models, demographic diversity or a network quorum.

Each seat receives these layers in order: its runtime/model constraints (with exact
model identity left unknown if the runtime does not expose it), its repository-root
governance and bounded local evidence, the steward's delegation, and this council's
purpose and limits. Use fresh agent contexts without the parent conversation. Brit
is read from its own root; the representative does not load Elohim's gospel as its
constituency. The Elohim seat does not inspect Brit's private context. Only the offer,
counterproposal, evidence and stated outcome cross between seats, never private
reasoning. This is prompt-level isolation, not filesystem sandbox isolation.

The bounded purpose is a reversible Rust-discipline trial. One offer and one
counterproposal are followed by at most two reconciliation rounds. An unresolved
issue returns to the steward rather than manufacturing consensus. Neither seat may
publish, spend, sanction, alter identities, enlarge its mandate, or bind the other
repository. Output pins the offered policy, adaptations, trial checks, dissent,
withdrawal conditions and unmet prerequisites. Local implementation may proceed
within the user's existing authorization; remote witnessing stays unproven.

For a collective, representation and the council's capacity must be declared from
the actual stewards and affected people, stakes and available attention/compute.
No population, demographic coverage, quorum threshold or capacity ceiling is inferred
from agent count. This micro case exercises two seats and bounded rounds only; it
does not establish a universal council size or a measured high-stakes ceiling.

The first encounter ran in fresh contexts and reached a conditional recommendation
in one reconciliation round. Brit independently verified the offered bytes and
proposed `brit-build-ref/**/*.rs` as its first trial scope, retaining upstream parity,
compiler checks and rollout authority; Elohim accepted. See `task-srd-4-report.md`
under sprints for the public outcome and technical prerequisites. This is evidence
of the encounter. Its subsequent local trial and standalone installation are recorded
in task-srd-5-report.md; committed enrollment and network adoption remain separate.

## Trial delivery boundary

The selected standalone delivery is an immutable addressed source bundle, containing
the checker and its first-party dependency sources. Its declared projection reduces
the EPRFS workspace to required members while retaining inheritance. The compiled
checker method pins those sources and the dependency lock. A normalized registry
package cannot supply that source layout; checker publication remains disabled.

Missing station discovered during review: between first addressed enrollment and
later successor acceptance, an explicit checker migration must verify the historical
method/baseline, preserve debt accounting and change only the accepting repository.
Probe: accept a new guide/checker locally, retain the old version in the other space,
and prove both checks and prior evidence remain meaningful. The initial trial refuses
replacement of an enrolled closure; generic local policy imports support deliberate
repinning, but that does not establish this checker's migration support.

Story-graph discovery: between adopting held policy bytes and checking changes to
those bytes, gate selection must include explicit governance inputs without marking
application pipeline sources stale. Probe: change only an addressed policy object;
both path and Rakia selection choose the local Rust-style gate, and no application
pipeline is dispatched. The focused graph/registry/gate-runner suite passes
(88 passed, one environment-dependent skip). This is a local quality boundary,
not a new deployment trigger or a remote witness.
