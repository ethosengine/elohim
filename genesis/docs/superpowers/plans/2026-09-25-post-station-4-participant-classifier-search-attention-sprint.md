# Post-station-4 sprint

## Context

Station 4 of governed discovery landed on dev 2026-09-24: the native semantic route, the fold as
an `IndexMeasure`, rank fusion, an FTS5 lexical provider declared, and the fold-lag headline. The
operator then named what follows and reframed the first item: identity must come from the
operator's own device contexts (an Eclipse Che workspace, VS Code on an Ubuntu laptop, anywhere),
never from the host, so the human claim has to be portable and device-native. The other three
directions are taken as slices of the same sprint. This plan is written for Opus 5.5 implementers;
Fable holds the vision, rules on forks, reviews alignment, and dispatches.

**What is true on disk today (explorers, 2026-09-24):**

- The `human:` grammar landed (station 1) but nothing is signed, claims are per session in a
  gitignored per-workspace sidecar, and no human claim has ever been written. `elohim-epr` already
  holds the ed25519 keypair code and `bridges/did` already renders a key as `did:key`; the
  network-level shape for "a second device acts for this identity" is specified (`binds-identity`)
  with its validator written and its coordinator unshipped.
- The classifier's primitive exists in Rust (`elohim/epr/src/witness.rs`, `FrameClassification`
  with a content CID), the validator seam already lets a validator return a verdict with
  evidence, and the harness-neutral git gate is live. No frame atom exists; the two ontology
  guards still carry hand-rolled phrase lists; all 11 gap items are OPEN.
- Lamad's search is client-side over a capped content list; the list route drops tags and trust,
  so tag scoring runs on empty arrays. The native index lives only in the recall executor, and
  elohim-storage may not depend on any eprfs crate. FTS5 is already compiled into the storage
  binary through lair's bundled SQLCipher.
- The observation layer is mostly built (wire type, tables, GET routes, gossip types, manifest
  kind `lamad:content-viewed` with `dwell_ms` and `scroll_depth_pct`) but has no write path and
  the manager is never started. Dwell is written today as an `AttentionTending` record, which the
  governed-discovery spec classifies as a lens preset, and as a DHT `EconomicEvent`.

**Prior art:** every lane refines a canonical spec (frontmatter `refines:`); no standalone spec
is minted. The p2p-design-gate answers are inherited from those specs; this plan adds no new
entity class (Lane P's roster row is the `binds-identity` rehearsal; Lane S's view and Lane A's
view are Category C projections; Lane C's frame atoms are S2 sources).

**Position:** MAP domain D2 (evidence primitives: attestation ↔ observation) for Lanes P and A,
D4 (memory lifecycle) for Lane S, process-meta `hooks`/`memory` for Lane C. The roadmap's
2026-09-09 regeneration predates the recall work and ranks none of this; the nearest rung is
Sprint 4 (living-memory substrate gaps). Ledger and focus numbers are trusted over that prose.
All four lanes are testable on `household-nodes`; nothing here is BLOCKED-BY-ENV.

**Habit register:** two habits are active (the WIP fence); the two new habits this plan declares
(`guards-sense-frames`, `attention-witnessed-privately`) are born `active: false`, red, with
runnable checks and a `retire-when`.

### Design rulings (Fable; cost-if-wrong in the ledger at pickup)

- **R-P1 The floor stays honor-system; the ceiling rises.** A device signature makes a claim portable and self-verifying. It never becomes a credential: no refusal path anywhere reads a signature, `source:` gains one value (`claim-signed`) beside `claim | unclaimed`. This dissolves the §6 tension without reopening it.
- **R-P2 Handle is a name; the chain root is the identity.** `human:<handle>` stays the display grammar. The durable id is the `did:key` of the first device that claimed the handle (the genesis of the lineage), exactly the identity-head spec's chain-root idea rehearsed at the repo node. A second device mints its own key and is bound, never handed a copy.
- **R-P3 The device key lives outside every checkout.** `${XDG_CONFIG_HOME:-$HOME/.config}/elohim/device/ed25519.seed`, 0600, load-or-generate with the `node_identity.rs` hardening (O_EXCL temp + link, first writer wins). One key per OS user per device; every worktree and every Che restart of the same PVC sees the same key. Override `ELOHIM_DEVICE_KEY_FILE` for tests only. Che ephemerality is the operator's to judge: if the PVC is wiped the device is a new device and is bound again, honestly.
- **R-P4 Second record kind, never a new field.** `ActorRecord::Signed { claim_cid, signer: did:key, signature }` keeps every existing claim CID byte-identical (the signature cannot sit inside the atom it signs). The doc comment reserved this variant.
- **R-P5 The roster is tracked, append-only, and carries only public material.** `.eprfs/status/participants/<handle>.jsonl` (new gitignore rung: tracked). Rows: `genesis {handle, chain_root: did:key A, signed by A}` then `binding {handle, chain_root, controller: did:key B, authorized_by: A, sig_A, sig_B}` — the two-halves shape of storage's `AgentPeerBinding` proof. Git is the transport at the repo node; the graduation is `mishpat::bind_identity`, no translation needed because `did:elohim` already renders controllers. Never an email, never a git name, never a Che namespace in a row.
- **R-P6 Standing, not per session.** A human claim is standing per device: the latest `Signed` human claim whose signer is in the handle's roster applies to every session on that device until the human claims otherwise. Agents stay per session. `current_for(session)` is untouched; a new `standing_human(roster, signer)` read sits beside it and the three attribution arms gain one arm between "session claim" and "git author": the standing human claim.
- **R-P7 `human` is a tier, ranked above every model tier** in `destructive-git-requires-tier@1`; `_resolve_tier` maps a `human:` claim to it. The operator is the team the gate asks for.
- **R-P8 Bindings via the ceremony, not via copying.** Enrolling a second device is three commands across two machines: `epr actor device enroll --handle <h>` on B prints a request (B's did:key + nonce); `epr actor device authorize <request>` on A prints an authorization signed by A; `epr actor device bind <authorization>` on B countersigns and appends the roster row. Commit + push carries it. No key ever crosses. The agent present on each device runs these, with the human present as the reason (R-P9).
- **R-P9 The elohim witness the human (operator ruling 2026-09-24).** The human's standing identity at the repo node is established by a **witness act of a present agent**, not by the human's self-declaration and never by the substrate. This is the DHT's `HumanityWitness` / `attestation:humanness` pattern (humanity is attested by others) taken up at the repo node by the agents working here, as the nascent elohim role with the responsibility and stewardship it carries. The record is `ActorRecord::Witness { subject: human:<handle>, witness: agent:<role>@<model>, session, basis: <one line the witness stands behind>, claimed_at }`, signed by the device key (the witness signs from the stewarded device it acts on), and it is the genesis row of the handle's roster (`chain_root` = that device's `did:key`). A witness is a participant taking responsibility, contestable by adverse attestation (in-flight claims spec §2.3), never an inference from git, email or the Che namespace; the basis names what the agent actually knows (the operator of this stewarded device, the name the workspace-device spec gives, the standing relationship in memory). **Witnessing is deliberate, once per device, by the agent who knows who is present; no hook ever witnesses automatically.** The human keeps the right to claim for themselves (`epr actor claim --as human:`) and to contest a witness; both rows sit in the same roster. Spec §2's "claimed by the human" gains this amendment (task P0).
