# Collective memory integration: local first slice

The ceremony now composes governed collective contributions, exact ephemeral context
and explicit paired burden measurements. The static relationship is `.epr-meta/collective.json`;
existing actor claims and flow observations carry attribution and lifecycle. No parallel
membership database, acceptance queue or core EPR kind was introduced. Memory-kit is
transitional: collective memory and `.epr-meta` own its two responsibilities.

Native implementation and measurement evidence are in task-1-report.md and task-2-report.md.
The ceremony adds linked collective/project/contribute/feedback/graduation operations,
bounded source outlines, verified continuation and explicit method adoption. Shared findings
are bound to their exact projection request; switching to an edge does not mix their standing.
Baseline and close are immutable, same-run/method/scope observations. Reports fold those
inputs; incompatible or incomplete observations refuse a comparable delta. Serialized
snapshot cost is counted; subsequent rendering, native log appends and reporting remain
explicitly outside the sample. Private runtime stores were not migrated.

Package-first changes updated memory-kit 1.1.0 and memory-ceremony 1.2.0, preserving
compatibility entry points while removing competing ownership and implicit latest-pair
claims. Retention now holds deletion pending verified pin/custody disposition. This protects
ignored evidence but does not yet deliver reference-aware retirement or net artifact reduction.
