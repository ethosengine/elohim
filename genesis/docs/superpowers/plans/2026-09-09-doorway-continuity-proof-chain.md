A visitor must receive the same declared working site when a doorway becomes unavailable.
This is the next bounded pass on doorway-failover, using the existing native recipe,
scenario commitments, report fulfilments and habit atom. No independent status ledger.

The proof graph joins two predecessors: current-source app delivery and canonical
household fixture readiness → broader household failover. App delivery uses its own
unclaimed root mount, so execute it before staging the canonical landing; these are
separate fixture states, not a command chain that overwrites an existing root.
Broader household failover plus health-aware shared membership precede actual apex
host routing through a shed and recovery → fleet serving of the identified release. App delivery's
2026-09-08 five-scenario green is already ingested with `epr flow fulfill`; the broader
10-scenario run's six failures are ingested as a regression, not erased by that green.
Edges declare prerequisites; v1 recipe edges do not enforce execution. Every station
retains its own observation and run witness, and unmet successors remain unfulfilled.

- [ ] A developer stages the named household landing and manifesto prerequisites without unrelated writes, then measures the complete household failover feature against the current runtime.

Reuse real packaged app outputs, exact seed-manifest blob bytes, existing owned-mesh
seed/projection/stage interfaces and exclusive fault lock. Targeted content seeding
currently enters unrelated ancillary seed phases; constrain that existing execution
path and verify writer calls, preserving full-seed behavior. Do not invent fixture
landing bytes or erase unrelated data. Missing fixtures must be observable before
fault injection. Gate the seeder/a2o owners actually touched.

- [ ] A beacon contributes only its own shared DNS records while its doorway serves, withdraws after three consecutive non-serving probes, and rejoins after two consecutive serving probes without changing exclusive diagnostic names or siblings.

Implement existing backlog A1 in relay-addr-beacon. The opt-in URL defaults unset;
probe interval defaults15s, leave3/join2, positive validated counts. HTTP200 is serving
regardless body; other statuses, redirects, timeout and connection failure are not.
Membership starts withdrawn with probing enabled until join evidence is earned.
Withdrawal cannot depend on WAN detection success or address change. Failed DNS writes
retry; no logs may claim applied state before successful writes. Preserve exclusive
DNS, pkarr and coturn behavior. No public DNS calls during verification; use existing
mock API with exact-owner removal, sibling preservation and failed-write/retry checks.

P2P gate: membership is Ephemeral C, reconstructed from existing `/health/serving`;
no new DHT entry, head, coordinator call, signal, storage table, content identity or
HTTP route. Its identity is the existing DNS-name/owner pair. Zero additional heads at
one year; DNA hash neutral. Serving is the existing status-code contract, not a new
protocol authority. Concern C7 advertise/serve symmetry, C6a bounded work, C6b retry
idempotence and C8 decision observability apply; implement at the beacon/bridge seam.

- [ ] An apex-transition story distinguishes shared address membership from actual host-to-doorway selection, and its final assertion cannot pass without observing a shed, sibling delivery of the declared head, and recovery.

Keep the existing visitor finish-line assertion. Add executable prerequisite stations

Do not certify public ingress via a test-only proxy. Prepare a coherent repo-owned

- [ ] A new agent can recover each station's current source, admitted run evidence, predecessor limits and remaining frontier using native flow context and ledger queries.

Bind the existing scenario surfaces and these gap intents into the existing recipe
registry. Ingest actual sprint reports; retain red/green history and source/environment

Fleet verification remains read-only until the final concrete release/deployment
boundary. The complete habit stays red while apex routing and fleet delivery lack
