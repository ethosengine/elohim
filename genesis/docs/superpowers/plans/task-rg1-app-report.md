Branch `regenesis/app`, worktree `/projects/elohim/.worktrees/rg1-app`, rebased onto `regenesis/storage` (bc0edbd64).

## What changed
- `raw-cid-verify.ts`: thin wrapper over `@elohim/epr` `addressForm`/`verifyAddress`. `verifyByteCid(bytes, address)` is true only for `addressForm === 'bytes'` plus a digest match; sha2 citation CIDs `(0x55,0x12)`, dag-cbor CIDs, `sha256-`/`sha256:`/bare hex all fail.
- Service worker: `CACHE_NAME = 'apps-v4'` (exported); `staleAppCaches` evicts `apps-v1..v3`; the capability probe reads `X-Content-Address` (was `X-Blob-Hash`); `blobHash` renamed `blobCid`; archives verified with `verifyByteCid`. `src/assets/apps-sw.js` was rebuilt with `pnpm run build:sw`; it is gitignored build output (`prebuild`/`prestart` rebuild it), so it is not in the commit. The rebuilt bytes contain `apps-v4` and no `sha256-`.
- Callers: `content.service.ts`, lamad `content-backend.service.ts` (a blob reference is `isByteCid`, nothing is normalized), `epr-resolver.service.ts` (`isContentAddress` = `addressForm !== null`; `normalizeContentAddress` deleted), `offline-view.repository.ts`, `epr-head.model.ts` and `epr-codec.ts` comments.
- `blobHash` to `blobCid` across app, lamad and library; lamad `blob-url.ts` fails closed to `''` on a non-byte-CID; `conductor-normalizer` drops `blob_hash`.
- lamad `blob-verification.service.ts` rewritten: local BLAKE3 (`@noble/hashes/blake3`) against the expected byte CID. The WASM, doorway-server, SubtleCrypto and SHA-256 tiers are removed (SubtleCrypto cannot compute BLAKE3; a clean break admits no second hash). Method literal `'blake3-js'`.
- `elohim-core/src/loader/loader.ts`: admits only a canonical byte CID, BLAKE3-verifies, rejects any other spelling by name (`Unsupported address ...`).
- Generated view copies under `app/*` regenerated by `pnpm run schema:codegen:ts` (never hand-edited): `blobCid`/`serverBlobCid`, `PutBlobResponseView` with profile/chunks/stripes.
- Specs: about 114 `sha256-` fixtures re-minted as real byte CIDs from real bytes (helper `app/elohim-app/src/app/testing/byte-cid.ts`, multiformats + noble); the remaining `sha256-` literals are negative tests and doc strings.

- SW caches: `apps-v4` (verified extracted bundles); `eprfs-objects` unchanged (keyed by CID, outside the `apps-*` purge). On `activate`, `staleAppCaches(await caches.keys())` is deleted, so `apps-v3` and every `sha256-` key go.
- SW key shapes: `{origin}/apps/{byteCid}/{path}` (bundle files; `byteCid` = `bafkr4i...`, 59 chars); `{origin}/apps/_heads/{slug}` (text body = last verified byte CID for the slug; page requests get 404). No `sha256-` key shape exists.
