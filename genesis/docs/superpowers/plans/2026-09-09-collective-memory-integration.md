# Collective memory integration

Deliver one local collective-memory journey through the existing ceremony. Memory-kit
is transitional: shared agent memory belongs to the collective; files/docs/algorithms/code
belong to EPRFS under `.epr-meta`. Keep useful analyzers as deterministic lenses, no third
memory authority. Private native runtime stores remain private and independently owned.

Authority: operator-approved 2026-09-09 design revision in the unified-memory-loop design.
Local B/C scope only, zero network heads; repository graduation is a local reach rehearsal,
not network enforcement. Reuse existing EPR kinds, BlobCid and REA process/review records.
The design's C0–C14 partial obligations apply. No core memory kind or implicit publication.

## Delivery stations

- [ ] Two collaborating agents can contribute and retrieve a governed memory concern with exact source versions, separate author/steward/scope/reach, preserved contradiction and traceable ephemeral projection; local graduation refuses restricted or unsupported evidence.

Native owner: first establish the static collective relationship in repository-local
`.epr-meta`, reusing existing collective/membership semantics and governed declaration
patterns. Memory references that declaration; do not create a separate membership or
stewardship registry. Distinguish declared local participation from network membership.
Then extend existing EPRFS agent/CLI composition and storage primitives; introduce
only the smallest typed contract required. Content-derived identity and immutable versions,
explicit selected inputs, no latest-write authority, no mutable competing acceptance queue.
A projection retains a receipt and reasons/omissions; feedback names source or projection.
Bound work and reject unknown contract fields. Test malicious paths, missing bytes, replay,
concurrent alternatives and local reach refusal. Expose usable CLI operations for ceremony
integration. Existing actors/flow observations carry lifecycle; do not claim new peer authority.

- [ ] The ceremony uses explicit comparable baseline and close observations with deterministic burden reports, safe evidence retention and visible incomplete measurements.

Measurement owner: repair the existing balance collector, retain a compatible entry point,
and bind method/scope/run/sampling timestamps. Count files/lines/bytes with safe paths;
separate authored, projected, retained and operational footprints without duplicate traversal.
Bound traversal and optional providers. No latest-snapshot pairing; unknown is not zero.
Repair retention's unverified Git-history assumption and protect pinned evidence by default.
Test net consolidation, added overhead, scope/method mismatch, flag semantics and ignored
report safety. Provide a small callable interface for ceremony entry/close integration.

- [ ] A fresh agent completes the integrated ceremony after context reset, challenges misleading context, preserves uncertainty and rehearses selective graduation; reports derive from pinned governed inputs and measure overhead without claiming unobserved token savings.

Integration owner: existing recall-ceremony, algorithm contract, planted memory-kit/ceremony
packages and devflow a2o scenario. Compose the two implementations into linked actions and
continuation; keep private native stores untouched. Add scenario before implementation.
Run appropriate native/Python/package/a2o gates and independent technical review, then one
fresh-agent observation using real work plus labeled adversarial fixtures. Preserve reviewed
artifacts and append one evidence delta to dev-system-equilibrium; leave RED absent rate proof.

## Execution boundaries

At most two implementation seats; scoped write sets. No commits or pushes in this sprint.
Use verified native binary, safe-directory environment and cargo berth/target policy.
Do not touch accepted prior ceremony plan/report bodies. Existing dirty edits are preserved.
Retire compatibility surfaces only when replacement coverage is proved; retain unresolved
migration work explicitly. Full network graduation and universal runtime adapters are outside
this local first slice. Evidence of this slice is not evidence of completed toolkit retirement.
