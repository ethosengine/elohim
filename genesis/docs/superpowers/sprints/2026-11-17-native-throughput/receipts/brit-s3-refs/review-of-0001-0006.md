### 2. Global `-C`

**NOT A DEFECT** for the order of plumbing operations. Brit applies successive nonempty `-C` values before explicit write-path guards, tracing, config loading, repository discovery and repository guards. Relative `-r`, `GIT_DIR` and `GIT_WORK_TREE` are therefore interpreted after the directory change. Both orders of `-C` and `-r` use the final cwd. The distinction from Git is the meaning of the selector itself. Brit’s `-r repo` starts discovery at `repo` and can find an ancestor. Git’s `--git-dir=repo` requires `repo` itself to be a Git directory. Also, `GIT_DIR` overrides Brit’s `-r` discovery fallback. `src/plumbing/main.rs:184`, `:199`, `:210`, `:275`, `:296`; `gix/src/discover.rs:93`; `gix/src/open/repository.rs:152`, `:352`.

### 3. Read-only classification

### 4. Broken pipe

**CONFIRMED.** The new test in the CLI error handler has no information about which descriptor failed. It accepts any matching cause anywhere in a Git error chain, including one whose *text* merely ends in `Broken pipe (os error 32)`. `brit-cli/src/main.rs:342`, `:352`, `:365`.

- **A real push rejection can disappear.** `push --porcelain` writes per-ref statuses before checking `any_rejected`. If the reader closes during those writes, `?` returns early and the top-level handler emits 141. The rejection exit of 1 is never reached. The verbose wrapper can likewise replace an already-computed operation error when forwarding buffered output fails. `gitoxide-core/src/repository/push.rs:793`, `:810`, `:841`; `src/shared.rs:79`.
- **A reader closing mid-output can still produce a diagnostic.** Build JSON and DOT output use `println!`, which can panic on a failed stdout write. `--cli-surface-json` also uses `println!` for its final newline after writing the JSON. A reader can accept the body and close before that newline. Clap help takes another route and discards the result of `error.print()`, allowing exit 0. `brit-cli/src/output.rs:7`; `brit-cli/src/commands/graph_show.rs:84`; `brit-cli/src/main.rs:268`, `:275`.
- **A regular-file error can be hidden.** For example, Tix adds `could not read commit message at <path>` to a failed file read. A filename ending in the magic suffix can make a permission or read failure qualify for silent 141. Ordinary `ENOSPC` or `EIO` alone does not match. `gix-tix/src/command/reword.rs:154`; `brit-cli/src/main.rs:347`.
