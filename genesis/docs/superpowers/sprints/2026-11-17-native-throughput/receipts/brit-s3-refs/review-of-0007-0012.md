## 2. Delta findings

### Repository discovery

**CONFIRMED — a mutating command can select a different repository.** Consider cwd `/outer/sub/.git`, where `/outer` is a repository, `/outer/sub` is an ordinary directory, and `/outer/sub/.git` is itself a worktree with valid metadata at `/outer/sub/.git/.git`. The old relative `.` has no filename, so discovery first probes `./.git` and finds the inner repository. The new absolute starting path ends in `.git`, so discovery probes `/outer/sub/.git` itself and skips its child. That probe fails on an ordinary worktree root. Discovery ascends and can find `/outer/.git`. A `branch create` would then use the outer repository. The mutation guard is acquired **after** selection, against the selected repository. This is a source-traced counterexample. `src/plumbing/main.rs:205–212,259,298–302,319–321`; `gix-discover/src/upwards/mod.rs:167–189,352,384–392`

The ordinary cases have a narrower result:

| Starting directory | Effect |
|---|---|
| Normal main `.git` | The intended repair works. I observed the correct private directory and HEAD. Passing `-r ./` bypassed the exact-string condition and reproduced the old `./.git/objects` failure. The old worktree conversion pops the presumed `.git` component and later appends `.git` again. `src/plumbing/main.rs:205–212`; `gix-discover/src/repository.rs:229–237,255–260` |
| `.git/worktrees/<name>`, `.git/modules/<name>`, or a descendant such as `.git/refs` | The predicate looks only at the final cwd component. For ordinary names it does nothing. I checked this checkout’s actual private worktree gitdir, its submodule gitdir, and a normal `.git/refs`. The default and `-r ./` selected the same gitdir and HEAD in each. `src/plumbing/main.rs:205–212`; `gix-discover/src/is.rs:107–121,143–164` |
| Bare repository | An ordinary `repo.git` or `repo` basename does not trigger the change. A directory named exactly `.git` does trigger it, even if it is bare. With a single valid repository there, the absolute probe validates that directory. A competing nested `.git` changes probe precedence as described above. `src/plumbing/main.rs:206–210`; `gix-discover/src/upwards/mod.rs:167–189` |
| Directory merely named `.git` | The name alone cannot pass repository validation. Without a competing child, discovery can ascend to the same ancestor. With a valid nested gitfile or gitdir, the skipped child is decisive. An explicit `GIT_DIR` takes the environment-open path. `gix-discover/src/is.rs:64–73,125–138`; `gix/src/discover.rs:93–98` |

The fix belongs where a validated `.` candidate is converted into a repository path. That preserves the original candidate order for every command.
