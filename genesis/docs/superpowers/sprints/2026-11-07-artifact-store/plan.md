## 0. Context (why, and the ground this plan stands on)

**Why.** Regenesis 1 landed the address profile so that the first artifacts minted on the dataplane are minted under the right identity. The next pain is the long roll: a storage or doorway binary is built by every device and by every CI stage, although its input closure has not changed (edge #1824 re-ran the doorway gate and build on a peer-fabric-only change; the local storage gate pays 817 s median, 2,071 s max, 5,757 s cold; `just mesh build` rebuilds the 454 MB storage binary on every device). The design's test for every move: *if every external runner and the forge disappear, do two workspaces still integrate and build between themselves?* Sprint 2 makes the first bytes move between the steward's two workspaces under a signed derivation record, and leaves every later rung (Jenkins as a carrier, a second principal, community reach) a widening of that record and path.

**One sentence (plan §7.3).** A sibling workspace fetches the mesh storage and doorway binaries (the 454 MB chunked case) from the steward's other workspace over the tier, verified chunk by chunk and whole, instead of rebuilding them, with every draw a `Use` and every build a `Produce`, on one byte store per device, and with nothing served that the requester's grant does not cover.

**Habit.** DELTA lands on `genesis/orchestrator/.epr-meta/sprint-lands-each-closure-once.habit.md` (red, inactive; its prize is this join) and, for the hardening lane, on `elohim/elohim-storage/.epr-meta/blob-durability.habit.md` (green). ## 1. Design-gate answers, once for the whole sprint (p2p-design-gate)

No new DHT entry type, table or HTTP route (plan §7.3 E4). **Classification:** artifact bytes are Ephemeral (C), rebuildable by re-running the method; the `DerivationRecord` is Attested-Private (B2) in brit notes and the tier manifest; the custody pledge is a local `custody-blob` commitment (B, born `self`) that graduates to the existing elohim-DNA `CustodianCommitment`/`BlobToReplicas`-class links only at release reach (D6) — **not this sprint**. **Identity:** content-derived — the binary's whole-bytes byte CID (`bafkr4i…`) is `record.output`; the layout/chunk manifest has its own record CID and a swap between the two is refused; the derivation key is `(method CID, projected input root)`; the gate's sha256 hex `closureKey` remains an index key into `inputs_hash`, never an address. **Head-plane cost:** zero DHT heads at `self`/`intimate` (R2); at 1 year, zero. **Coordinator function:** none; no zome changes; nothing moves a DNA hash. **Signal:** `Produce` on build, `Use` on fetch, `serve-blob` `Use` on serve, each a flow event with quantities (§10.7). **Reach:** lookup is reach-gated on the request (`AskPolicy::may_ask`, §10.9); serving enforces scope per root and object CID (§10.12); roster admission never authorizes general blob access (R3). **Local-first:** the first act is a local tier put that works with the daemon down (§10.4, §10.12a); the store absent, slow, uncredentialed or empty changes speed and reach, never a verdict (I4). **Transport:** the tier (eprfs-peer over iroh ALPN) is the byte path; a transport mode that cannot deliver is a typed gap, never a silent fallback.

**Concern canon for every new parser, record and envelope** (inherited from regenesis-1 §2.0, applied here): C0 fail-closed on unknown codec/multihash/scheme/epoch; C2 epoch on every wire object, unknown HELD; C3 bounded input (manifest size cap before allocation); C4 no string equality across namespaces (`ByteCid`/`Cid` newtypes); C5 verify-before-serve and verify-before-install; C6 durable before announce (marker last); C7 quarantine, never delete; C8 address ≠ authorization; C9 no dual-read; C10 one authoritative payload store; C13 generated artefacts regenerated, never hand-edited.

### 2.4 Interfaces and anchors for E3/E4/F2 — `design.md` governs

The verified design (Opus Plan agent, 2026-11-07, every anchor read on dev `6d994a931`) is `design.md` in this hub. It **supersedes the draft §2.4** written before it arrived. The rulings that change the rows above:

1. **E3's grant is per method, not per root.** `berth.artifacts.serves` in `pool-policy.json` (`{"mesh-build": ["steward"]}`), a third rule set beside `crosses` and `steward`, entered into `Rules::digest`. A new `eprfs-peer/src/serves.rs` (`ArtifactServeList`) and `blob_mount.rs` (`BlobMount`, an index rebuilt from the device's own flow store).
2. **`eprfs-serve` never calls `admit_object`** (`eprfs-serve/src/lib.rs:232,358,378,402,428`), so fixing `gate.rs` alone enforces nothing on objects. The blob answer path calls `admit_root` → `admit_object` → membership itself. Two `TierRequest` variants on the same ALPN: `Manifest { artifact }` and `Blob { artifact, cid }`.
3. **Strangers get a byte-identical uniform refusal**; an admitted device outside its grant gets a typed refusal (`OutsideStanding` with `serve-blob:<method>`, or `NotUnderRoot`). One `serve-blob` `Use` event per (requester, artifact) session, carrying no `measure:` slot so it never crosses.
4. **E4 relocates the store into `crates/elohim-blob-store`.** eprfs-peer and epr-cli may not link elohim-storage. `elohim-storage` keeps `pub use` shims. epr-cli gains `src/payload.rs` with a `STORE` format marker (`blob-store-v1 | directory-v1`; a mismatch is refused, never duplicated). Owner/shared opening: only the owner deletes, GCs or quarantines. **The `blob-store` feature defaults off until the H2 receipts**, then flips.
5. **F2 is native, not a new mjs module.** `epr artifact put|fetch` (`epr-cli/src/artifact.rs`) plus `epr peer artifacts --key` beside `verdicts`. `inputs_hash` is the `DerivationKey` CID string, never sha256 hex. The Produce event carries `measure: artifact-produce@1`, `reason: produce`, so it is both the local custody ledger and the crossing record. That adds one `crosses` entry and no second channel. An interim key over `epr bin source-state` is allowed only if labelled `basis-key:git-tree`, and it does not close F2.
6. **The daemon fetches.** A second endpoint on the device key is not viable, so `epr artifact fetch` queues `<peer_dir>/fetch-queue/<key>.json` and `Run::tick` runs `fetch::fetch_artifact`. No daemon means `FetchGap::DaemonDown` with its cure. The install read is `stream_local_blob` (whole-blob verify), which writes the `Use`.
7. **Chunks can be 4 MiB** (the landed epoch-0 profile supersedes §10.11's "≤ 1 MiB"). The 10 s server frame deadline (`tier.rs:65`) sets a ~420 KB/s per-stream floor. Below it a relay path is `TransportCannotDeliver{"relay"}`, typed, never a hang. 454 MB ≈ 433 chunks, a manifest ≈ 35 KB, a 1 MiB manifest cap, 8 in flight per holder, a 30 s stall and a 1800 s total.
8. **`epr bin` is not the path** for mesh binaries this sprint. Its ingest copies bytes into its own staging, so it would be a second copy. A convergence row goes to F5.
9. Write-set order: **E3 → F2** (shared `daemon.rs`, `local_blob.rs`, `peer.rs`); E4 after H2 and independent of E3. E2 and E3 share `tier_blob.rs` in disjoint hunks.
