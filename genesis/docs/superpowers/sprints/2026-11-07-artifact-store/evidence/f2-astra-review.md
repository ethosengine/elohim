1. **High — staging-file substitution bypasses verified installation.** [`fetch.rs:803`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:803), [`fetch.rs:830`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:830).  
   A local process able to write the destination directory can precreate `.<name>.fetching` as a symlink or hard link to an existing file. `File::create` follows/truncates it before verification; failure or a crash can therefore leave partial, unverified bytes in the existing destination. Alternatively, replacing the staging pathname while its original inode is streamed makes `rename` install the replacement, although verification covered the original inode. Use exclusive, private staging and protect the pathname-to-inode relationship through publication.

2. **High — queue responses can report success for the wrong installation.** [`artifact.rs:920`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:920), [`artifact.rs:927`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:927), [`fetch.rs:948`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:948).  
   Requests and responses are identified only by derivation key. Two callers requesting the same key for different destinations share both filenames; either can consume the other’s completion. A late completion from a timed-out request can likewise satisfy a later request. The CLI accepts any deserializable `Installed` response without checking its key/output, and the response contains neither destination nor request nonce. An existing stale executable can consequently be reported as fetched and pass `mesh_fetch`’s `chmod`. Bind completion to a unique request, destination, key and output.

3. **High — the method does not cover the effective build environment.** [`artifact.rs:540`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:540), [`artifact.rs:595`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:595), [`hc-mesh.sh:2047`](/projects/elohim/.worktrees/as-f2/app/elohim-app/scripts/hc-mesh.sh:2047).  
   Cargo inherits the caller’s environment, while the descriptor records only `RUSTFLAGS` and explicitly supplied `mesh_build_env` entries. Changing inherited `CARGO_ENCODED_RUSTFLAGS` or Cargo profile overrides can change compilation without changing the key. Config discovery records crate-local files, not all ancestor or user Cargo configuration. Thus materially different builds can be published under one key and silently reused when only one holder exists. Deviation 3’s claim that widening the view prevents unkeyed build changes is unsupported; effective inputs must be captured or excluded from the build environment.

4. **High — “clean” does not establish the bytes Cargo read.** [`artifact.rs:273`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:273), [`artifact.rs:342`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:342), [`artifact.rs:720`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:720).  
   The closure hashes HEAD objects and trusts ordinary porcelain status. A tracked symlink can read an out-of-view target whose changes do not move the key. Ignored build inputs and changes hidden by index flags or submodule-ignore configuration can also escape this check. For a directly selected file, the closure records its object ID without its entry mode/type. Finally, modifying source during compilation and restoring it before `put` passes both endpoint checks. A dirty computation can therefore be recorded against the clean closure. Deviation 2 improves validation but does not prove its stated during-build guarantee.

5. **High, conditional on queue write access — the queue is an unrestricted daemon command surface.** [`daemon.rs:1232`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1232), [`daemon.rs:1258`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1258), [`daemon.rs:1325`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1325).  
   The daemon checks key self-consistency and holder admission, but does not recompute the local closure or re-resolve the crossed records/conflicting outputs. A queue writer can select another artifact and any destination writable by the daemon, including outside its stores. Moreover, `next_request` accepts non-regular files and the synchronous, unbounded read occurs before filename validation: a FIFO can block the daemon tick; a large file can exhaust memory.  
   This is a same-account/shared-directory attack, **not an established cross-UID privilege escalation**: a correctly protected peer directory prevents unrelated users from writing the queue.

6. **Medium — `total` is not a whole-fetch deadline.** [`fetch.rs:549`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:549), [`fetch.rs:621`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:621), [`daemon.rs:1325`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1325).  
   After manifest acceptance, secondary holders are dialled sequentially with a full `stall` each, outside the total timeout. Several unreachable holders can exceed `total` before the chunk loop checks the deadline. Resume checks, storage writes and installation are also outside a common deadline. The CLI’s timeout does not cancel an already claimed operation. Deviation 6 therefore overstates the bound; use one absolute deadline through completion and explicit cancellation.

7. **Medium — wasted-byte accounting is inaccurate.** [`fetch.rs:668`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:668), [`fetch.rs:682`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:682).  
   A corrupt answer is charged the expected chunk length regardless of its actual size. A holder can send a tiny corrupt answer and be charged a full chunk, or send substantial partial/malformed answers that reach the generic error/timeout branches and are charged zero. Deviation 8 weakens §3’s measurement requirement. Actual received/discarded byte counts must survive transport errors.

8. **Medium — the consumer does not enforce the stated relay floor.** [`fetch.rs:607`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:607), [`tier.rs:458`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/tier.rs:458).  
   A malicious relay-only holder can deliver a 4 MiB answer in 20 seconds and satisfy the default 30-second client timeout. The honest server’s ten-second `write_all` timeout neither constrains a malicious server nor measures client delivery throughput. Deviation 7 does not implement §3.b.5’s floor; slow delivery can succeed instead of producing the specified transport gap.

9. **Medium — producer and daemon can use different payload stores while `put` reports success.** [`artifact.rs:775`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:775).  
   With an explicitly configured daemon store and a `put` lacking that override, the custody Produce reaches the daemon’s flow store but its bytes land elsewhere. Siblings discover an artifact the builder’s daemon cannot serve. Deviation 10 is an unresolved availability defect; the proposed E4 fix does not establish correctness in this reviewed change.

The core network integrity checks are sound on the inspected path: manifest CID, key and expected output are checked; chunks are checked by CID and length; reconstruction follows manifest order and verifies the complete output before `Completed`. Mixed manifests cannot bypass that final hash. The manifest frame cap is checked before body allocation, and chunk retries are bounded by abandoning holders. Without local staging interference, a process crash before rename leaves the previous destination intact.

Both producer and consumer use `closure_key`. View normalization and the distinct absent/gitlink encodings do not themselves reveal a collision; the failures concern incomplete inputs and working-tree observation.

Crossing also checks out: the builder writes `artifact-produce@1`/`produce`; fetching writes only a Use. [`blob_mount.rs:782`](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/blob_mount.rs:782) requires a local-receiver Produce without `via:`. Fetching alone grants neither custody nor onward serving.

Deviations **1, 4, 5, 9 and 11** preserve §3’s relevant boundaries; **2** has the limitation above, and **3, 6, 7, 8 and 10** need correction or an explicit revised ruling. The labelled Raw key remains an allowed interim, not F2 closure. Finally, byte verification proves correspondence to the holder’s declared output—it does not prove that an admitted malicious builder actually computed that output from the claimed sources.
