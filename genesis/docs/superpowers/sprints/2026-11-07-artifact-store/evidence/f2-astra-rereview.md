**BLOCK** — static review only; no tests or builds run. None of the blocking findings below depends on Sybil identities.

1. **H1 — Partially closed. High; same-account process.** Exclusive creation in private random staging closes predictable precreated links ([fetch.rs:984](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:984)). Publication remains vulnerable at [fetch.rs:1029](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:1029): inode checks neither prevent the acknowledged rename race nor detect **in-place modification of the same inode**. Another process under this account can overwrite an already-streamed portion; verification covered the incoming bytes, and both inode checks still pass. Residual **3** therefore understates the exposure: substitution can return success, and the detected variant already overwrites `dest` before reporting failure. A fallback build is not rollback.

2. **H2 — Original request-collision attack closed; forgery remains. High; same-account queue writer.** Random request nonces and four-field equality separate concurrent requests and stale completions ([fetch.rs:1225](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:1225), [artifact.rs:1202](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1202)). However, those fields are readable from the request. A same-account writer can copy them into a forged `Installed` response; the CLI does not verify the installed bytes. Cancellation likewise accepts **any filesystem entry** at another request’s `.cancel` pathname, without reading its identity ([daemon.rs:1262](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1262)). This requires observing the nonce, not predicting it.

3. **H3 — Original Cargo-variable examples closed; effective-input coverage remains incomplete. High; single admitted producer or same-account process.** `env -i` excludes inherited Cargo overrides, and ancestor/user configuration contents now enter the key ([hc-mesh.sh:2061](/projects/elohim/.worktrees/as-f2/app/elohim-app/scripts/hc-mesh.sh:2061), [artifact.rs:518](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:518)). But inherited `PATH` still reaches compilation without entering the descriptor ([hc-mesh.sh:2056](/projects/elohim/.worktrees/as-f2/app/elohim-app/scripts/hc-mesh.sh:2056)); native tool variables record strings, not the tools or libraries selected ([artifact.rs:889](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:889)). Different native compiler/linker resolution can therefore retain the same key. Doorway also executes `git` through that unkeyed PATH ([build.rs:39](/projects/elohim/.worktrees/as-f2/doorway/doorway-service/build.rs:39)).

4. **H4 — Not closed. High; same-account process.** Entry modes, direct escaping symlinks, top-level index flags and submodule-ignore settings now receive checks ([artifact.rs:357](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:357), [artifact.rs:596](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:596)). Nevertheless, `put` still checks only the final working-tree state ([artifact.rs:1045](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1045)). Residual **1** accurately describes an unchanged original attack: edit during compilation, restore before `put`. It remains blocking. Residual **2** also preserves the ignored-input hole: [artifact.rs:563](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:563) excludes every `node_modules` component, but nothing prevents a build script or source inclusion from reading it. This is a conditional reopening of H4, not an enforced input boundary.

5. **H5 — Partially closed, with a new scope-escape race. High; same-account queue writer.** Regular-file checks, `O_NOFOLLOW|O_NONBLOCK`, and capped reads close the original FIFO/oversized-entry paths ([fetch.rs:1391](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:1391)). Install-root validation rejects static outside paths. However, it returns a pathname after canonicalization ([fetch.rs:1082](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:1082)); installation resolves that pathname again after the network fetch. Replacing an admitted parent directory with a symlink during that interval redirects installation outside the scope, while the installed inode checks can still pass. The daemon also still trusts the queued key/output/holder selection without independently resolving conflicting records ([daemon.rs:1316](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1316)). `EPR_INSTALL_ROOTS` is read at daemon startup, so changing only the queue writer’s environment does **not** widen a running daemon’s scope.

6. **M6 — Partially closed. Medium; operational and same-account cancellation race.** Parallel secondary dials and the shared absolute timeout close the original sequential-dial overrun ([fetch.rs:609](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:609), [fetch.rs:673](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:673), [daemon.rs:1391](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1391)). But synchronous flush/fsync/rename cannot be interrupted by that async timeout; publication can occur after the deadline ([fetch.rs:1025](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:1025)). Withdrawal also races: the daemon can finish reading a request before the CLI successfully removes it; the CLI then writes no cancellation marker, yet the daemon proceeds ([daemon.rs:1292](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/daemon.rs:1292), [artifact.rs:1285](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1285)). Finally, `abort()` is reported as `Cancelled` without awaiting termination, allowing an already-running synchronous publication to finish afterward.

7. **M7 — Partially closed. Medium; single admitted holder.** Completed corrupt/malformed answers now use actual received-byte counts ([tier.rs:716](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/tier.rs:716), [fetch.rs:781](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:781)). Counts still disappear when the **outer** deadline drops request tasks: their counters are task-local, and the resulting gap carries no wasted count ([fetch.rs:740](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:740)). Manifest deadline returns also bypass accumulation ([fetch.rs:529](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:529)). Partial length headers are uncounted because counting follows successful `read_exact` ([tier.rs:701](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/tier.rs:701)). I found undercounting, not a negative-count or double-count path.

8. **M8 — Original declared-relay-only example closed; actual-route enforcement remains incomplete. Medium; single admitted holder.** The consumer now applies the ten-second bound to a 4 MiB request classified as relay-only ([fetch.rs:375](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:375)). Classification uses advertised addresses, however, not the connection’s actual transport ([fetch.rs:347](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:347)). A configured holder with an unusable direct address and a working relay retains the longer direct-path bound even when traffic travels through the relay. Rejecting an honest connection genuinely below the declared floor is expected policy behavior; it is not independently a defect.

9. **M9 — Stable configured mismatch closed; fail-open path remains. Medium; same-account process or daemon-startup race.** The daemon records its canonical store, and `put` compares it ([peer.rs:758](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/peer.rs:758), [artifact.rs:1014](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1014)). But an unreadable/missing marker returns success even while the serving lock is held ([artifact.rs:1009](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1009)). Removing that marker restores the original mismatch. Startup also acquires the lock before writing the marker, leaving a missing/stale-record interval.

10. **Residual 5 — Not an acceptable nonblocking residual under the operator ruling. High; single admitted malicious builder.** `put` accepts supplied bytes and labels their derivation `Computed` ([artifact.rs:1060](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1060), [artifact.rs:1112](/projects/elohim/.worktrees/as-f2/elohim/eprfs/epr-cli/src/artifact.rs:1112)). One holder’s output passes resolution without independent computation evidence ([fetch.rs:1154](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:1154)). A malicious admitted builder can supply mutually consistent key, manifest, chunks and output for an executable it did not compute. The limitation is honestly disclosed, but it is **single-peer**, not Sybil-class, and therefore blocks under the stated ruling.

11. **New — Deadline fix misclassifies genuine holder failures. Low; operational classification, triggerable by one holder.** [fetch.rs:386](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:386) treats the final **20 ms before** the deadline as already expired. A full stall timeout—or an immediate dial failure—inside that window becomes `DeadlineExceeded` despite remaining budget ([fetch.rs:453](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:453), [fetch.rs:816](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:816)). The code should distinguish which bound expired rather than infer it from a tolerance window.

12. **New — Crash-orphaned staging accumulates. Medium; operational crash recovery.** Cleanup exists only in `Drop` ([fetch.rs:930](/projects/elohim/.worktrees/as-f2/elohim/eprfs/eprfs-peer/src/fetch.rs:930)). Unwinding and ordinary future cancellation execute it; SIGKILL, aborting panic and process crashes do not. Fresh random directories mean subsequent attempts neither reuse nor remove abandoned artifact copies. Repeated interrupted large installations can exhaust disk. Queue pruning covers answers/cancellations, not staging directories.

Medium; operational compatibility, no demonstrated exploit.** The production build command now uses the new allowlist ([hc-mesh.sh:2061](/projects/elohim/.worktrees/as-f2/app/elohim-app/scripts/hc-mesh.sh:2061)), but the author explicitly reports no real Cargo build under it. Static inspection does not establish that it is too narrow, and I do not claim such a failure. This residual does not itself reopen a proven security finding; it leaves build compatibility unverified and does not resolve H3’s remaining input-coverage problem.
