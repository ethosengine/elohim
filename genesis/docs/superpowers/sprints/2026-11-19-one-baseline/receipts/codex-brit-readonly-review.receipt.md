### Exit status and output

**The new JSON recognition is typed and correct for the case it adds.** It downcasts `gix::Error`, finds a `serde_json::Error`, and checks `io_error_kind()`. There is no message matching. An already-returned nonzero `ContextExit` or plumbing status wins. With `read_only == false`, the closed-reader logic cannot synthesize 141. An admitted command that ran a writing helper, however, has `read_only == true` and can receive 141 after that write. [`brit-cli/src/main.rs:362`](./brit-cli/src/main.rs#L362), [`brit-cli/src/main.rs:400`](./brit-cli/src/main.rs#L400)

**A genuinely failing invocation can exit 141.** In a valid repo, `brit --no-verbose tree info no-such-revision` with default human output writes a format warning before resolving the revision. With live stderr it reaches the invalid revision and fails. With closed stderr the warning returns EPIPE, the lookup never runs, and `exit_status()` returns 141. The analogous stdout case is a streaming query such as `exclude query` that prints a valid first path before validating a later one. Also, at the classifier level, the process-wide boolean records *some* watched EPIPE, while the downcast searches *anywhere* in the returned error. Neither establishes that the returned error consists solely of that watched write. The JSON addition does not create the underlying distinction. [`gitoxide-core/src/repository/tree.rs:174`](./gitoxide-core/src/repository/tree.rs#L174), [`gitoxide-core/src/repository/exclude.rs:54`](./gitoxide-core/src/repository/exclude.rs#L54), [`src/shared.rs:53`](./src/shared.rs#L53), [`brit-cli/src/main.rs:413`](./brit-cli/src/main.rs#L413)

**A successful printing invocation can also miss 141.** `brit show HEAD:path` on a short blob with no newline copies the blob into stdout’s line buffer. `write_diff_output` flushes the scratch writer, then copies to stdout. Neither that copy nor `prepare_and_run` flushes stdout before `main` reads `seen()`. The buffered bytes can first encounter EPIPE during process cleanup, after Brit has chosen 0. The same issue applies to short newline-free JSON such as `[]`. The new build helper’s explicit flush is correct. [`gitoxide-core/src/repository/show.rs:141`](./gitoxide-core/src/repository/show.rs#L141), [`gitoxide-core/src/repository/diff.rs:1191`](./gitoxide-core/src/repository/diff.rs#L1191), [`gix-utils/src/stream.rs:351`](./gix-utils/src/stream.rs#L351), [`src/shared.rs:104`](./src/shared.rs#L104), [`brit-cli/src/main.rs:558`](./brit-cli/src/main.rs#L558)

**Shared error reporting has a deliberate exception to the literal “every write is watched” claim.** The final diagnostic uses fallible raw stderr *after* the status decision. A bad `-C` likewise uses fallible raw stderr and returns 128. Both correctly preserve the failure and avoid a panic. Clap also prints help and parse errors before normal command classification. Optional EPR feedback runs after status selection and can record the invocation or print a capture-gap diagnostic. That existing behavior qualifies any whole-process claim that the command changes nothing or is always silent. [`brit-cli/src/main.rs:469`](./brit-cli/src/main.rs#L469), [`brit-cli/src/main.rs:555`](./brit-cli/src/main.rs#L555), [`src/plumbing/main.rs:267`](./src/plumbing/main.rs#L267), [`brit-cli/src/feedback.rs:54`](./brit-cli/src/feedback.rs#L54), [`brit-epr/src/diagnostic.rs:45`](./brit-epr/src/diagnostic.rs#L45)
