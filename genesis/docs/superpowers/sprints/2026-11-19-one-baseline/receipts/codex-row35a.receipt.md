### Blocking findings

1. **A healthy release can be reverted for another process’s failure, or before its own readiness clock expires.** X serves, Y lands, and the new peer on Y becomes ready. An unrelated declared worker stays down. `patience` sums every probe of every process, `not_ready` requires every process, and witness selection also includes every process. At expiry the code holds Y and reverts it to X, even though the peer passed. The scope fix is small but needs to cover three places: select the children on the landed channel in `child_identity`, then use those same names for readiness and witnesses. Today the tool filter only establishes that *some* declaration uses the tool, and `child_identity` returns the first stale child on *any* channel. Separately, the outer deadline starts after a fixed 1.5-second ark watch, while ark starts each rung’s patience after spawning the child. Slow resolution, hashing, scheduling, or passport publication can consume the outer budget before ark has exhausted the child’s. With no declared probes the budget is zero, so a healthy child whose PID has not yet been published gets exactly one read. Filtering the names alone does not fix the clock. `supervise.rs:51,513–540,880–886,984–1013`; `restart.rs:267–279,306–319,325–345`; [ark’s rung deadline](/projects/elohim/.worktrees/nt-l2a-review/elohim/ark/supervisor/src/supervisor.rs:648), [spawn and passport publication](/projects/elohim/.worktrees/nt-l2a-review/elohim/ark/supervisor/src/supervisor.rs:930).

2. **Failure between stopping X and entering the readiness wait is reported as a successful landing.** Y lands, `supervise` stops X, and the new ark exits during `START_WATCH`, or startup fails writing the manifest, berth, log, or supervisor record. `start_ark` returns an error before `settle` can hold Y or restore X. The bin adapter prints “the landing … stands” and returns `Ok(())`. The immediate-exit case leaves Y current, no HELD mark, and no peer. A full disk during `receipt.hold` takes the same success branch after failed readiness. There is a second unmonitored path: if the manifest changed as well as the binary, startup returns `stale: None`, which `after_landed` classifies as `Untouched` even though it replaced ark. A failure after the startup watch on that path gets no readiness check. `supervise.rs:316–324,403–438,906–918,1013,1214–1231,1259–1285`; `bin.rs:443–463`.

3. **Rollback dismantles supervision before establishing that the previous release can be restored.** After Y times out, the code writes HELD, stops ark, and only then creates `revert-<pid>` and tries `land_expected`. A missing previous commit in the caller’s clone, ENOSPC, an occupied worktree path, or an admission refusal leaves Y current and held with no ark. Killing the caller after the head moves but before `start_ark` leaves X current with no ark. Subsequent automatic settlement explicitly skips a stopped ark. Even a successful atomic head change followed by a symlink-repair error is treated as a refused revert, so X can already be current when recovery declines to start it. Worktree removal is attempted after a returned store error, but a kill skips it, a removal failure is only logged, and PID reuse can collide with the leftover directory. **Gitlink tools have a deterministic version of this failure:** `current.json.commit` is the submodule commit, whereas `worktree add` runs in the containing repository. An ordinary superproject cannot check out that object as its own prior tree. Recovery needs to pin its inputs before stopping and leave enough durable state to finish an interrupted restore. `supervise.rs:888–890,1047–1065`; `bin.rs:471–499`; [gitlink source identity](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/device-runtime/src/bin_store/source.rs:242), [head publication and subsequent repair](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/device-runtime/src/bin_store/landing.rs:363).

4. **HELD is bypassed by ordinary arrival and by several ark start paths.** Follow fails on Y and successfully restores X. The next long arrival runs the unpinned follow through `execute_with(..., false)`, which also disables the hold checks. Pinned arrival calls `store.follow_declared` directly. Either can put Y back in `current`. A same-manifest supervise can leave X running because it sees the hold, but ark resolves the channel again on a later child spawn. Cold hand supervise, manifest reload, and handover also reach `start_ark` without the stale-child hold check. With `leave`, the failed ark is left running and its own restart policy can retry held Y. Bootstrap can adopt a held cached candidate, and explicit revert/rebase land skips the readiness hold. A custom data root adds another bypass: once ark is stopped, `device_data_root` falls back to the caller’s default root and can no longer find the original hold. An unreadable or malformed hold file is also read as an empty map. The guard belongs at candidate promotion and at spawn admission, independently of whether the caller requests post-landing supervision. `bin.rs:67–73,169–177,275–299`; `supervise.rs:316–348,386–418,1021–1036,1099–1105`; `restart.rs:185–190`; [arrival’s pinned and unpinned arms](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/epr-cli/src/device/arrival_work.rs:73), [arrival’s long follow](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/epr-cli/src/device/arrival_work.rs:207), [bootstrap promotion](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/device-runtime/src/bin_store/lifecycle.rs:177).

5. **Two follows can attribute the wrong transition and revert more than one step.** Follow A reads X as its `before` and pauses. Follow B lands X→Y. A resumes from a checkout at Z, its store operation observes Y and legitimately lands Y→Z, and its outer adapter reads Z. If Z fails, A requests Z→X. `Some(Z)` passes the store’s current-CID check, so Y is skipped. A no-op or observe follow can likewise see another caller’s change between its two reads and initiate a restart for a landing it never made. Same-session lease renewal allows both callers through, and there is no per-ark serialization between inspecting its PID and replacing it. A second race occurs during readiness: if a later landing advances current, the older recovery stops its ark *before* the store refuses its now-stale revert. Use the exact prior/current pair from the committed store operation and revalidate ownership of the restart before stopping anything. `bin.rs:282–299,420–441`; `supervise.rs:295–300,388–418,1047–1055`; [follow’s own expected prior](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/device-runtime/src/bin_store/lifecycle.rs:625), [store comparison](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/device-runtime/src/bin_store/landing.rs:308), [same-session renewal](/projects/elohim/.worktrees/nt-l2a-review/genesis/agentic/bin/berth:1613).

6. **The device pointer can select the wrong live root and the wrong policy.** The copy beside the key contributes only `data_root`. Its PID, start ticks, manifest, and ark path are discarded. The selected root qualifies if its *own* `supervise.json` names a live PID with matching ticks. The foreign-ark scan rejects extra arks using the berth but does not require the recorded PID to be an ark using that berth. A stale pointer to another still-running supervised root can therefore direct the stop, restart, hold, and receipts there. This requires access to the private state or an already-stale pointer. The copy uses `NamedTempFile`’s Unix `0600` default, and newly created containing directories request `0700`; existing directories are not tightened. Independently, a legitimate `--data-root` outside the default layout has no recorded checkout. A follow from a separate clone then reads **that clone’s** committed `restart/revert` policy, even if the device checkout declares `off/leave`. The same fallback selects the berth executable. `supervise.rs:295–307,874–892,908–910,1090–1115,1276–1295,1341–1350,1746–1761`.

7. **An unresolved session can restart under another session’s live lease.** With the genuine berth and a resolvable different session, the author’s claim holds: capacity one refuses the claim before `stop_ark`, the follow leaves the landing standing, and the holder retains its lease. But berth returns `EXIT_NO_SESSION` before checking the live holder when session resolution fails. `claim_lease` explicitly treats exit 4, a missing berth, or a disabled berth as permission to proceed unleased. An unattended follow can therefore stop the holder’s ark without taking its lease. The recovery start also calls `start_ark` directly with no renewed ownership check. `supervise.rs:386–418,1057–1059,1677–1707`; [berth session resolution](/projects/elohim/.worktrees/nt-l2a-review/genesis/agentic/bin/berth:2581), [live-holder refusal](/projects/elohim/.worktrees/nt-l2a-review/genesis/agentic/bin/berth:1641), [device-ark capacity](/projects/elohim/.worktrees/nt-l2a-review/genesis/agentic/pool-policy.json:157).

### Confirmed behavior and follow-ups

- **Ordinary no-op paths.** With no competing writer, equal before/after CIDs skip supervision. A landing of a tool with no declared channel consumer also skips it. A routine arrival with nothing moved and no stale child makes no supervise call. A revert calls the store directly, so it cannot recursively enter `after_landed`. If X also fails after rollback, `settle` makes no third ark start or second revert. That bound applies to the landing operation; ark’s own child restart policy still operates. The claim that settlement *witnesses both* is too strong: the degraded receipt reuses Y’s witness, and there is no second witness lookup for X. A readiness timeout need not produce a death witness at all. `bin.rs:420–423,492–495`; `supervise.rs:880–890,1004–1013,1038–1045,1070–1084`; [arrival guard](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/epr-cli/src/device/arrival_work.rs:121).
- **Stale readiness.** An ordinary passport left by the old ark does not immediately pass: each child PID must currently have the newly started ark as its parent, and that ark’s own start ticks are checked each poll. However, the reader does not compare passport incarnation, child start time, or artifact identity. A recycled PID belonging to another new child can satisfy the old row, and a stale or unreadable row can consume the entire deadline in finding 1. Ark already publishes child start time and artifact hash. `restart.rs:309–317,325–345`; [passport fields written by ark](/projects/elohim/.worktrees/nt-l2a-review/elohim/ark/supervisor/src/supervisor.rs:973).
- **Hold lifetime and precision.** I found only explicit `--release <cid>` removing an entry. Landing another release does not clear the old entry. The reverse problem is that follow’s precheck searches all holds by checkout commit, without a tool qualifier, even after seeing a different explicit closure CID. A distinct release built at the same commit can be refused. `supervise.rs:226–231,1153–1163`; `restart.rs:209–222`; `bin.rs:385–406`.
- **Policy values.** For the default device root, the read is `git show HEAD:genesis/agentic/pool-policy.json` in the inferred device checkout. Git location overrides are removed. Missing file, failed Git read, malformed JSON, absent switch, and non-string values retain `restart/revert`; unknown strings retain those defaults with a warning. A recognized switch still applies when its sibling is unknown. `off` exits before supervision, and `leave` holds the release and skips the revert callback. The custom-root checkout exception is finding 6. `restart.rs:110–158`; `supervise.rs:892–900,1013–1036`; [Git command environment](/projects/elohim/.worktrees/nt-l2a-review/elohim/eprfs/epr-cli/src/git.rs:506).

VERDICT: FIX FIRST

- Bind readiness and failure attribution to the landed tool and the new child’s actual startup.
- Recover and report failures after the old ark stops, including early ark exit and failed HELD writes.
- Make one-step rollback recoverable across Git, disk, interruption, and gitlink failures.
- Enforce HELD on every automatic promotion and spawn path.
- Bind settlement to the actual store transition and coordinate racing restarts.
- Bind the root and policy checkout to the intended device and running ark.
- Require lease authority before an unattended stop or restart.
