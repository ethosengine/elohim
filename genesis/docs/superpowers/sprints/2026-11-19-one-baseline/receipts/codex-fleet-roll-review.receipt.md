### 2. Can the hook break a valid push?

**Yes. The main shell issue is exit behavior, not quoting.** The new loop initializes its accumulator, reads fields with `read -r`, and quotes its expansions. The hook enables `pipefail` and deliberately leaves `-u` off. I found no ordinary unset-variable or quoting failure in the new block. `.husky/pre-push.bash:32,1048–1057`.

- **Refusal timing.** `leg_red` records a failure and returns under the default `continue` policy. An early pass or the final aggregation eventually refuses, but selected project gates can run first. This fails the stated requirement that the *push* be refused within seconds. `.husky/pre-push.bash:902–933,1057,1742,1781`, `genesis/agentic/pool-policy.json:199`.
- **Unreadable remote tip.** If the advertised object is absent, the hook substitutes `origin/dev`. That fallback can omit real destination changes or include commits already on the destination, including an old declaration. If `origin/dev` is also absent or lacks a merge base, the existing change detector refuses before the new block. A known, readable remote tip needs no `origin/dev` for this check. On a protected update, an unknown destination range should produce a specific refusal, not a confident verdict from a different branch. `.husky/pre-push.bash:982–995,1039,1052–1054`.
- **Node, dependency or walker failure.** The dedicated CLI has no catch. An unreadable or invalid manifest throws, Node exits nonzero, and the shell records a red in *any* mode that reached the walk, including `warn` and a `self/*` push. A missing Node executable or import fails even for notes-only pushes and before `off` can be read. The message promises a cure even when the preceding output is just a stack trace. In contrast, the ordinary preflight catches a thrown walk and emits a generic `WARN`, so a protected legacy-hook invocation can pass. A protected `refuse` check should refuse an indeterminate decision. Advisory contexts should warn, and excluded refs should need no evaluator. `genesis/orchestrator/manifest-utils.mjs:20,38`, `genesis/orchestrator/gate-preflight.mjs:387,436,458`, `.husky/pre-push.bash:1057`.
- **Long ranges.** `spawnSync` buffers the complete formatted history with its default 1 MiB output limit. A valid large range can therefore refuse with a “fetch origin” cure that cannot fix it. The record delimiter `0x1e` can also occur in a commit body and make a valid tip look like multiple messages. `guard:264–280,151–156`. A failed write of the paths file has a separate hole: the shell marks narrowing unavailable, but the guard can still read a truncated, valid-looking list. `.husky/pre-push.bash:1006–1014`, `genesis/orchestrator/gate-preflight.mjs:409`.

### 3. Can ambient environment variables change the result?

**The current hook protects the dedicated invocation against the four named variables.** It replaces `GATE_CHANGED_FILES`, `GATE_PUSH_TARGETS` and `GATE_PUSH_RANGES`. Its `--fleet-roll` entry ignores an inherited `GATE_FLEET_ROLL_DONE=1`. ### 4. Policy modes

**An unreadable policy is not a silent `off`.** `refuse` refuses a predicted undeclared protected roll. `warn` downgrades that refusal. `off` returns before reading messages or walking, and also disables the separate `skip-ci` warning. A missing file, missing key, unknown mode, malformed JSON or read error defaults to `refuse`. The checked-in mode is `refuse`. The fallback is silent about *why* it chose that mode. Exceptions outside policy loading have the inconsistent behavior described above. `guard:84–89,145–155,288–295`, `genesis/agentic/pool-policy.json:203`.
