## Byte profile (WEAKENED → survives as amended)
1. **Validator = full decode.** `bafkr4i` + length 59 + alphabet admits a header `01 55 1e 21` (33-byte digest declared, 32 supplied) and non-zero padding. Every validator — kernel, DNA wasm, doorway, TS — decodes the full 36-byte canonical form, requires `01 55 1e 20`, rejects trailing bytes, and requires canonical re-encoding equality. Negative vectors are part of the conformance set. **Consequence:** no hand-written wasm predicate; the DNA zomes depend on the same tiny crate (see kernel).
2. **External checksums are evidence, not identity.** Cargo `.crate` sha256, npm integrity, OCI digests stay algorithm-labelled evidence verified on ingestion; the native BLAKE3 identity is computed from bytes after they arrive. **ark's artifact contract crosses too** (`elohim/ark/core/src/task.rs:234` requires a raw sha256 CID pin) → new small track T11 ark.
3. iroh key for an admitted byte CID = `Hash::from_bytes(cid.hash().digest())` (never `Hash::new`). Key compatibility only; availability is separate.
4. **A persistent transport cache is a second copy.** The `http.rs:4273` duplication into FsStore is deleted; persistent iroh-blobs delivery is **off** this sprint; FsStore becomes the one store only after the R1.4 receipts (durability, recovery, scoped serving, quarantine, obligation-aware retention — its tag-based `forget` is not per-obligation release). Pure-iroh byte delivery is a sprint-2 item with those receipts.
5. **Chunk lists are authenticated.** The store's `index/<cid>` is a dag-cbor layout record `{artifact_cid, byte_len, profile, chunks[(cid,len)]}` whose own CID is written into the marker; every full read recomputes the whole-artifact BLAKE3 before returning bytes (decision 4 reversed: whole-blob verification on read, always; BLAKE3 makes it cheap); range reads wait for bao (sprint 2). Reordering/substitution tests join the corrupt-chunk tests.
6. **Representation ≠ identity.** Inline iff exactly one chunk (so ≤ 4 MiB); `MAX_INLINE_SIZE` deleted; RS admission threshold is config, but every manifest records its full parameters and readers use recorded parameters, never current thresholds; two producers may hold different representations under one payload CID.
7. **One Rust addressing kernel, not mirrors.** New wasm-safe crate `crates/elohim-address` (deps: cid, multihash-codetable sha2+blake3, blake3, sha2, a base32 decoder; no ts-rs, no tokio) exporting `ByteCid::parse`, `compute_bytes_cid`, `compute_raw_sha2_cid` (cites), `compute_record_cid`, `verify_cid_any`, the negative/positive vectors; consumed by elohim-epr, eprfs-core, brit-epr (via Nexus publish), elohim-storage, doorway, rakia-executor, DNA zomes (path dep), steward. `short_fingerprint()` refuses non-sha2 digests. FastCDC and the signature envelope stay in `elohim-epr` (fastcdc is not needed in wasm).

## CDC (WEAKENED → survives as amended)
1. **Immutable spec.** Profile text pins fastcdc `=5.0.0` v2020 as reference, `with_level(1)`, unseeded published gear tables identified by digest, unsigned mod-2^64 arithmetic, scan/reset/cut/EOF semantics; TS twin uses BigInt. No seed field.
2. **Protected vectors.** Fixture generator frozen: xorshift64* (state 64-bit, shifts 12/25/27, multiplier 0x2545F4914F6CDD1D), seed `0x454c4f48494d` as hex string, length 10,485,760, input digest recorded; fixtures: empty (zero chunks), 365 B, min/avg/max ±1, odd length, repetitive, forced max, short tail; streaming with varied buffer splits equals one-shot; **existing epoch vectors are compare-only even under `EPRFS_WRITE_VECTORS=1`**; a changed expectation needs explicit review and, on behaviour change, a new profile id.
3. **RS id binds the code.** `rs-gf8-0x11d-v1` = GF(256) poly 0x11d, systematic Vandermonde construction (reed-solomon-erasure 6.0 semantics), index ordering, zero padding + truncation; parity vectors and every 4-of-7 reconstruction pinned, padded inputs included.
4. **Bounded stripes.** RS runs over consecutive stripes of ≤ 16 MiB original bytes: four contiguous data shards of `ceil(stripe_len/4)` + three parity; the manifest declares stripe order, original lengths, shard indices, lengths, CIDs. The 454 MB artifact acceptance includes actual shard transport and 4-of-7 recovery, not local reconstruction only.
5. Parameters stay experimental; measure distribution, byte-weighted reuse, bytes moved, manifest overhead, Rust/TS CPU and memory on successive binaries and wasm. Final chunk may be below min; empty input → zero chunks.
6. Identity split survives: artifact CID over bytes; layout record CID separate; whole-byte verification before accepting an imported representation; the profile is persisted with every layout (including the store index).

## The amended R1, as recorded (supersedes plan §7.4 R1 on the byte profile)
Epoch 0 newly produced native payloads — content, SPA/SSR bundles, artifacts, binaries, chunks, erasure shards — are addressed by CIDv1 raw (0x55) + unkeyed BLAKE3-256 (0x1e, 32 bytes); payload size never selects a hash. Structured records stay dag-cbor + sha2-256; citation fingerprints keep their sha2 construction; Holochain entry hashes are unchanged. External checksums (OCI, Cargo, npm) remain labelled evidence verified on ingestion, never native identity. Canonical byte strings are fully decoded and canonically re-encoded before admission; digest verification never grants authorization. One Rust addressing kernel (`elohim-address`) serves every Rust consumer including the zomes; TypeScript twins share adversarial conformance vectors. Chunk layouts are authenticated records bound to the whole-payload CID; delivery verifies the whole payload. Representations (inline, CDC chunks, RS stripes) carry their full parameters and may differ per producer under one payload CID. Each device has one authoritative payload store; iroh's FsStore qualifies only after the R1.4 receipts, and a persistent duplicate cache never does. The clean break removes legacy native address spellings; it does not erase external checksum semantics or preserved historical evidence (brit notes on their frozen preimage, memory lineage, steward heads, citations).
