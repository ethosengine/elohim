# Memory team becomes a triadic operating system

## Direction

The three temporal-perspective agents (librarian/present, historian/past, cartographer/future)
plus the orthogonal storyteller (meaning) become the operating system for how this codebase
keeps faith with itself across many cycles, many operators, and many model generations.
Right now they're a coordinated audit team running their first ceremony. By Q3 2026 they
should be:

- **Signal-coupled, not cadence-coupled** — every ceremony fires from accumulator threshold,
  never from "it's Tuesday"
- **Mutually composable** — a librarian's dedupe-cluster routes directly to a cartographer's
  next-actions menu; a historian's precedent surface routes directly into the operator's
  next /shift; a storyteller's graduation decision retires memory entries automatically
- **Time-transitive** — entries flow through the comet (live → working → graduated /
  memorialized / archived) without manual choreography
- **Self-disciplining** — the team notices when it itself drifts (MEMORY.md size, agent
  catalog staleness, skill-catalog overlap) and surfaces it as signal, not as a chore

## Why this matters

The codebase is large, the dev cycle is fast, and the operator is one human. Without a
substrate that keeps memory alive on its own terms, the project drowns in either over-cleanup
(losing context) or under-cleanup (drowning in stale). The triad design exists precisely
to avoid both failure modes: signal-driven so we don't over-clean, distillation-disciplined
so we don't under-clean.

This is also a sandbox for `project_agentic_context_graph_model` — typed-baton hand-offs,
velocity-tiered memory, consolidation events. The memory team is the smallest viable
instance of the larger architecture.

## What it would feel like to have achieved this

- Operator asks "what's next?" → cartographer responds with a 3-item menu in <60s,
  every item with vision×readiness score citing live signals
- Operator asks "is anything stale?" → librarian responds with a count and a triage
  list, no chore-language
- Operator asks "have we hit this before?" → historian surfaces precedent + risk in
  one paragraph
- Operator never asks "is MEMORY.md too big?" because the team already noticed and
  fixed it before the question arose
- A new agent (a 5th perspective, say "constitutional" for governance-layer audit)
  can plug into the same pattern without reinventing the substrate
