# Scale-risk cluster

A **risk** row is a concern with a *measurable trigger* that has not fired. It is filed here at
the moment the code that carries it lands, not when it bites. The discipline (tag, row shape,
where each row is surfaced and recalled) is in `genesis/data/timeline/CONVENTIONS.md` §Risks.
Sibling: the 2026-07-11 DHT scale-envelope entry holds the *planetary* question; this cluster
holds the *landed-code* shapes, each pinned to a file and a number.

Every row names the smallest change that retires it and the surface it graduates to. A row that
fires flips to `regression` (with the receipt) and gets a chronicle entry; the row itself stays
until the mitigation lands.

## Rows — what a hosted human's conductor must actually run (row 7 decomposed, 2026-10-16)

Operator question (2026-10-16): what really needs to be running in a hosted human's conductor, and
can the always-on parts consume a shared runtime (an ark guest, a live-session host, a hub)
instead? The answer splits row 7's cost by **what needs the person's own cell**. Only four things
do: signing their own actions (their keys are in this conductor's keystore), draining their
publish queue, reading their private entries, and calls addressed to their key (remote calls,
signals, countersigning, all rare in our flows). Reading what they already published, following a
forum, and links addressed to them do not: DHT holders serve the first two, and links wait on the
DHT until the cell wakes. The rule these rows hold: **a shared runtime serves, syncs and shows
presence, but never signs as the person** (the same line as "keys and compute never confer
authority"). The operational guard rail for alpha while these rows are open is
[doorway-hosted-capacity-bound-from-pod-memory](epr:doorway-hosted-capacity-bound-from-pod-memory).
Ordered cheapest first. Nothing in this section is re-measured; each row names its probe.
